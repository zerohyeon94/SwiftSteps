- 전날 Daily의 오늘 수행 목록 체크박스를 진도 판단의 단일 기준으로 사용한다.
- 완료한 항목만 다음 자료로 진행한다.
- 미완료 항목은 같은 체크박스 문구, 파일 또는 URL, 단계, 주제와 완료 기준을 다음 날 그대로 이월한다.
- Mobile, Go·React, IT 동향, 투자 기초 학습, 오늘의 상식은 서로 독립적으로 판단한다.

- 한 항목의 미완료가 다른 항목의 새 진도를 막지 않는다.

## 학습 축별 기본 방식

### Swift·Kotlin Mobile

- Swift 70%, Kotlin 30% 비중으로 같은 언어 개념을 비교한다.
- 설명과 코드 조각을 읽고 옳은 설명, 실행 결과, 오류 코드, 올바른 코드와 언어 차이를 체크박스로 선택한다.
- 모든 코드 블록에는 변수·함수의 역할과 실행 흐름을 쉽게 이해할 수 있는 한국어 주석을 넣는다. 문제 코드의 주석은 정답 대신 관찰할 지점을 알려 준다.
- 정답과 해설은 기본으로 닫힌 답변 콜아웃에서 확인한다.
- Daily 완료를 위해 코드를 직접 입력하거나 실행할 필요는 없다.
- 새 개념 Day 5개마다 누적 복습을 한 번 진행하며, 복습은 Day 번호를 올리지 않는다.

### Go·React 풀스택

- Go/API → PostgreSQL → React → Linux → 통합·Docker → Windows → 종합 검증 순으로 진행한다.
- 모든 Day를 설명과 코드·명령·설정 예시 읽기, 체크박스 선택, 접힌 정답과 해설 확인으로 진행한다.
- Go·JavaScript·TypeScript 등 프로그래밍 언어 코드에는 쉬운 한국어 주석을 넣고, JSON·로그처럼 주석이 원문을 바꾸는 형식은 블록 앞뒤 설명으로 보완한다.

- Docker Linux와 실제 Ubuntu 호스트, WSL2와 Windows 네이티브 환경의 차이는 상황형 선택 문제로 구분한다.

4. 오늘 Daily를 생성하거나 보강한다.

전날 항목 중 하나라도 미완료이면 커밋 제목과 본문에 진행하지 않음을 기록한다. Daily에는 피드백·회고·학습 메모를 새로 만들지 않는다.

6. 다음 날 아침에는 완료한 항목만 다음 자료로 진행하고 나머지는 그대로 다시 표시된다.

## Daily와 채팅이 연결되는 전체 방식

### 1. 사용자가 질문하면

사용자가 Swift, Kotlin, iOS, Android, Go, React, AI, Python 또는 다른 기술 질문을 하면 Codex는 고정된 시작 문구를 요구하지 않고 질문에 바로 답한다.

답변 전에는 현재 Daily와 질문에 관련된 기존 Conversations 학습 파일을 먼저 확인한다. 이렇게 해야 오늘 진도, 이미 읽은 내용과 기존 설명을 중복하지 않고 이어서 답할 수 있다.

### 2. 채팅에서만 답하는 경우

다음과 같은 경우에는 파일을 만들지 않고 채팅에서 바로 설명한다.

- 짧은 개념 확인
- 워크북 선택지 해설
- 현재 학습 순서에 관한 질문
- 오늘 학습량 조절
- Daily 체크 상태에 관한 설명
- 오늘 내용을 간단히 피드백해 달라는 요청

채팅에서 답했다는 사실만으로 Daily가 완료되지는 않는다. 다음 날 진도를 올리려면 사용자가 Daily의 해당 학습 체크박스를 직접 완료해야 한다.

추가 질문 멘토링을 사용하지 않은 것도 이월 사유가 아니다. 오직 Daily의 핵심 학습 체크박스만 완료 여부를 결정한다.

### 3. 별도 답변 파일을 만드는 경우

답변을 나중에 다시 읽을 가치가 있거나 기존 학습 내용을 보강해야 하면 관련 Conversations 폴더에 별도 파일을 만든다.

- 기존 학습 파일이 1. 주제명이라면 후속 질문은 1-1. 질문 요약, 1-2. 질문 요약처럼 이어 간다.
- 새 대주제라면 해당 분야 폴더에서 1. 소주제로 시작한다.
- 새 답변 파일을 만들면 연결된 기존 학습 파일에 답변 링크를 추가한다.
- Daily에는 같은 답변 링크나 별도의 멘토링 체크박스를 중복해서 만들지 않는다.
- 답변 파일 생성은 Mobile 또는 Go·React의 Daily 완료 여부를 자동으로 바꾸지 않는다.

### 5. 질문 종류별 Codex의 동작

#### 오늘 해야 할 것을 요청한 경우

전날 커밋, Notion 투자 페이지 준비, 오늘 Daily 작성의 세 단계를 수행한다. 이 요청에서는 프로젝트 코드를 수정하거나 문제를 대신 해결하지 않고 사용자가 수행할 자료만 준비한다.

#### 특정 기술을 질문한 경우

해당 분야 멘토로 답한다. 필요하면 Conversations 답변 파일을 만들고 기존 학습 파일에 연결한다.

#### 오늘 내용을 피드백해 달라고 한 경우

실제 체크 상태와 대화 내용을 근거로 채팅에서만 피드백한다. Daily에 피드백, 회고, 학습 메모 섹션을 만들거나 커밋하지 않는다.

#### 프로젝트 구현이나 오류 수정을 요청한 경우

명시적으로 요청받은 프로젝트 범위에서 코드를 확인하고 구현하거나 수정한다. 아침 Daily 생성은 프로젝트 구현 권한을 자동으로 포함하지 않는다.

#### 블로그나 포트폴리오 정리를 요청한 경우

별도 요청으로 초안이나 정리 파일을 만든다. Mobile 누적 복습이 끝났다는 이유만으로 Daily에 자동 추가하지 않는다.

#### 단기 목표를 요청한 경우

3일, 5일, 1주 또는 2주 단위로 목표, 마감일, 일별 체크포인트와 완료 기준을 정한다. 활성화된 목표는 핵심 학습을 침범하지 않는 작은 단위로 나누어 선택 확장에 반영할 수 있다.

#### 주식이나 투자 내용을 질문한 경우

금융 개념과 용어를 설명하지만 특정 종목 추천, 매수·매도 판단, 투입 금액 지시와 수익률 예측은 하지 않는다.

## Today.md의 역할

[[Today]]는 새로운 계획을 따로 저장하는 파일이 아니다. 오늘 날짜의 Daily와 오늘 수행 목록을 보여 주는 고정 진입점이다.

- 상단의 오늘 Daily 전체 열기를 통해 원본 Daily로 이동한다.
- 오늘 수행 목록은 오늘 Daily의 같은 섹션을 임베드한다.
- 체크박스를 Today와 Daily에 두 번 복사하지 않는다.
- 현재 안내 링크는 오늘 수행 목록 안에 있으므로 Today에서도 이 페이지로 이동할 수 있다.
- 날짜가 바뀌면 Today의 모든 Daily 링크와 임베드 날짜를 오늘 날짜로 갱신한다.

표준 Today에는 홈, 오늘 Daily 전체 열기와 오늘 수행 목록 임베드만 둔다.

## 이전 Daily에서 진도가 반영된 실제 예시

### 2026-08-01부터 2026-08-03

Mobile Day 4 함수와 매개변수, IT 동향, 투자 Day 9와 국민건강보험 상식이 미완료 상태로 반복 이월되었다. 2026-08-03에 각 체크박스가 완료되면서 다음 자료로 진행할 수 있게 되었다.

### 2026-08-04부터 2026-08-06

Mobile은 Day 5 Optional과 Nullable Type으로 진행했다. 2026-08-04와 2026-08-05에 미완료였기 때문에 같은 파일이 유지되었고, 2026-08-06에 완료되어 다음 날 누적 복습을 배치했다.

IT 동향, 투자와 상식은 Mobile과 별도로 체크 상태를 판단했기 때문에 각자의 완료 시점에 맞춰 새 자료로 진행했다.

### 2026-08-07부터 2026-08-10

새 개념 Day 1~5가 완료되어 2026-W32 누적 복습이 배치되었다. 누적 복습 Daily 체크박스가 계속 미완료였기 때문에 2026-08-10까지 같은 복습 파일이 유지되었다.

2026-08-09에는 Go·React가 두 번째 핵심 학습으로 새로 시작되었다. 2026-08-09 체크박스가 미완료였기 때문에 2026-08-10에는 같은 Day 1 파일이 이월되었다.

2026-08-09의 IT 동향, 투자 Day 13과 세 개의 상식 읽기도 모두 미완료였으므로 2026-08-10에 그대로 다시 표시되었다.

이 예시는 한 분야의 날짜가 아니라 각 체크박스의 완료 시점이 진도를 결정한다는 것을 보여 준다.

## 아침 Daily 생성의 세 단계

### 1단계: 전날 내용 커밋

전날 Daily와 전날 Daily에서 직접 연결된 다음 생성 자료만 하나의 학습 작업 단위로 커밋한다.

- Conversations의 직접 연결된 학습·답변 파일
- Learning/IT Trends의 직접 연결된 IT 동향 파일
- Learning/General Knowledge의 직접 연결된 상식 읽기 파일
- 사용자가 명시적으로 생성한 Learning/Stock Basics 파일

AGENTS.md, Profile.md, 사용자가 별도로 작업 중인 프로젝트 파일과 관련 없는 변경은 이 커밋에 포함하지 않는다.

핵심 학습과 일일 루틴 중 하나라도 미완료이면 커밋 제목과 본문에 진행하지 않음을 명확히 남긴다. 모두 완료했으면 학습 기록으로 커밋한다. 같은 작업 단위가 이미 커밋되었거나 변경이 없으면 중복 커밋하지 않는다.

### 2단계: Notion 투자 페이지 준비

전날 Daily의 투자 기초 학습 체크박스를 단일 기준으로 사용한다.

- 체크박스가 완료이면 연결된 Notion 페이지 상태를 완료로 맞추고 다음 Day 페이지를 준비한다.
- 체크박스가 미완료이면 다음 Day나 오늘 날짜의 이월 페이지를 새로 만들지 않는다.
- 미완료일 때는 전날 페이지의 실제 제목과 URL을 그대로 사용한다.
- 투자 공부 창고와 Daily 투자 학습 허브도 같은 페이지를 계속 가리키게 한다.
- 페이지 준비에 실패하면 존재하지 않는 링크나 로컬 대체 페이지를 만들지 않는다.

### 3단계: 오늘 Daily와 Today 갱신

전날 Daily의 다섯 학습 축을 각각 확인한다. 완료된 축만 다음 자료를 만들고, 미완료 축은 같은 항목을 이월한다.

오늘 Daily가 없으면 새로 만들고, 이미 있으면 기존 사용자 체크와 작성 내용을 보존한 채 부족한 링크만 보강한다. 마지막으로 Today가 오늘 Daily의 오늘 수행 목록을 가리키는지 확인한다.

## Daily 파일에 들어가는 표준 구조

### 핵심 학습

- Mobile 읽기·선택 퀴즈 또는 누적 복습 1개
- Go·React 풀스택 읽기·선택 퀴즈 1개

각 체크박스 아래에는 로드맵, 학습 모드, 단계와 Day, 오늘 주제, 완료 기준, 신규·이월 상태와 수행 순서를 함께 둔다.

### 일일 루틴

- IT 동향 1개
- Notion 투자 기초 학습 1개
- 오늘의 상식 1개

### 선택 확장

활성 단기 목표나 사용자가 요청한 보조 학습이 있을 때만 만든다. 수행할 선택 확장이 없으면 소제목도 생략한다.

### 만들지 않는 영역

- 시간대별 일정
- 회사 업무와 수강생 과제
- 날씨와 이동 시간
- 마무리 과제
- 전날 피드백 확인
- 학습 메모와 실습 메모
- 오늘 하루 정리와 개념 연결
- 오늘 하루 피드백과 저녁 회고
- 멘토링 시작과 추가 질문
- 오늘의 짧은 읽기

## 일요일과 주간 대화

### 일요일 아침

평소 Daily 학습 준비와 별도로 채팅에서 이번 주 진로 탐색 질문을 하나 제시한다.

- 현재 핵심 포지셔닝은 iOS를 기반으로 Android 네이티브까지 확장한 모바일 엔지니어다.
- 의료기기 펌웨어, 헬스케어 앱, AI 경험을 함께 활용하는 방향을 우선 검토한다.
- On-device AI, 헬스케어·BLE·IoT, 모바일 양쪽 플랫폼, 멘토링·강의 가능성을 함께 본다.
- 한 번에 결론을 정하지 않고 사용자 답변에 따라 매주 조금씩 좁힌다.
- 방향 변경이 확인되면 Profile.md의 관심 방향 갱신을 제안한다.

진로 질문은 핵심 학습 체크박스와 별개의 대화이며, 답변하지 않았다고 Mobile이나 Go·React가 미완료로 처리되지는 않는다.

### 일요일 저녁

그 주의 Daily 7개를 읽어 완료와 미완료 흐름을 파악한 뒤 대화식 주간 회고를 진행한다.

1. 완료, 미완료와 관찰된 흐름을 요약한다.
2. 질문 2~3개를 제시하고 사용자 답변을 기다린다.
3. 답변을 반영해 다음 주 방향 초안을 제안한다.
4. 사용자가 확인하거나 수정한 뒤 확정한다.
5. 필요하면 Weekly Review 노트 작성을 안내한다.

사용자 답변을 받기 전에 결론이나 다음 단계 전체를 임의로 확정하지 않는다.

현재 운영 판단은 다음 순서로 한다.

1. [[AGENTS|Codex 학습 시스템 지침]]
2. [[Profile|사용자 프로필과 현재 목표]]
3. 오늘과 전날 또는 가장 최근 Daily

7. 해당 분야의 기존 Conversations 학습 파일과 템플릿

CLAUDE.md와 GEMINI.md는 이전 운영 기록으로만 참고하고 새 Daily 기준으로 사용하지 않는다.

[[Schedule/근무 후 학습 루틴]]에는 과거 시간대별 학습, 영어회화 필수와 직접 작성 마무리 같은 이전 기준이 남아 있다. 이 내용이 AGENTS.md나 Profile.md와 충돌하면 현재 기준 문서를 우선한다.

## 현재 등록된 자동화와 최신 규칙의 차이

현재 Codex 데스크톱에는 두 자동화가 활성화되어 있다.

### 오전 5시 30분 자동화

이름은 전날 피드백·커밋·노션 투자 학습 준비이며, 이전 프롬프트에는 다음 구 방식이 남아 있다.

- 전날 Daily에 피드백 섹션 작성
- 학습 메모와 직접 작성 영역 확인
- Notion에서 개인 자산 입력과 피드백 반영 확인
- 커밋 제목에 피드백 기록 포함

현재 기준은 Daily에 피드백과 직접 작성 영역을 만들지 않고, 투자 학습도 개인 자산 입력 없는 순수 지식 읽기로 운영하므로 이 프롬프트와 충돌한다.

### 오전 6시 자동화

이름은 매일 오전 Daily Note 생성이며, 이전 프롬프트에는 다음 구 방식이 남아 있다.

- Mobile, IT 동향, Notion 투자 학습 세 항목만 독립 판단
- 평일 이론, 토요일 통합 실습, 일요일 재작성 구분
- 전날 피드백 확인 섹션 생성
- 멘토링 시작과 오늘의 짧은 읽기 섹션 생성
- Today에 네 개의 이전 섹션 임베드

현재 기준은 Mobile, Go·React, IT 동향, 투자와 상식의 다섯 축을 독립 판단하고, 평일·주말 구분 없이 같은 Mobile 읽기·선택 방식을 사용한다. 따라서 자동화 프롬프트도 최신 AGENTS.md 기준으로 갱신해야 다음 실행에서 구 방식이 다시 나타나는 것을 막을 수 있다.

## 현재 표준과 2026-08-10 Daily의 차이

현재 [[2026-08-10]]에는 이전 자동화 형식에서 남은 다음 섹션이 있다.

- 전날 피드백 확인
- 멘토링 시작
- 오늘의 짧은 읽기

현재 기준에서는 이 세 섹션을 새 Daily에 만들지 않고 오늘 수행 목록만 사용한다.

오늘의 상식도 표준 1개보다 많은 세 개가 이월되어 있다. 이는 2026-08-09에 생성된 세 항목의 체크박스가 모두 미완료였기 때문에 실제 Daily에는 그대로 반영된 상태다.

이 안내 페이지와 2026-08-10 Daily는 아직 현재 작업 트리의 새 파일이다. 아침 Daily 커밋은 AGENTS.md와 Profile.md 같은 운영 규칙 파일을 자동으로 포함하지 않으므로, 운영 규칙과 자동화 설정 변경은 별도의 의도적인 작업 단위로 커밋해야 한다.

이 페이지는 현재 상태를 확인하기 위한 안내다. 표준과 차이가 있다고 해서 기존 Daily의 체크 상태, 사용자의 문제 선택과 과거 학습 기록을 자동으로 수정하지 않는다.

## 빠른 확인 요약

- Daily는 학습 큐이고 Today는 그 큐를 보여 주는 고정 입구다.
- 다음 날 진도는 전날 Daily 체크박스 하나로 판단한다.
- 다섯 학습 축은 서로 독립적으로 새 진도 또는 이월을 결정한다.
- Mobile은 읽기·선택 퀴즈이며 Daily 완료를 위해 코드 실행이 필요하지 않다.
- Go·React는 모든 Day를 설명 읽기·코드와 명령 예시 읽기·체크박스 선택·정답과 해설 확인 방식으로 진행한다.
- IT 동향, 투자와 상식은 각각 독립된 읽기 자료다.
- 기술 질문과 피드백은 채팅에서 답하며 필요한 경우에만 Conversations 답변 파일을 만든다.
- 채팅을 했거나 답변 파일이 생겼다는 사실만으로 Daily가 완료되지는 않는다.
- 피드백, 회고, 멘토링 시작과 짧은 읽기 섹션은 현재 표준 Daily에서 제외한다.
- 현재 자동화 프롬프트에는 이전 운영 방식이 일부 남아 있어 최신 규칙과의 정합성 점검이 필요하다.
