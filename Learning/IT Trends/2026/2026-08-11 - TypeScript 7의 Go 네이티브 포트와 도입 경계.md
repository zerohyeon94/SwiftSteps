## 한 줄 요약

TypeScript 7은 컴파일러와 언어 서비스를 Go 기반 네이티브 구현으로 전환해 전체 빌드에서 8~12배의 속도 향상을 제시하고, 더 빠른 도구 체인과 기존 생태계 호환성을 함께 검증해야 하는 전환점을 만들었다.

## 왜 지금 볼 만한가

TypeScript는 React 같은 프런트엔드 프로젝트에서 오류 검사뿐 아니라 자동 완성, 정의로 이동, 리팩터링, CI의 타입 검사에 계속 개입한다. 따라서 컴파일러가 빨라진 변화는 빌드 시간만의 이야기가 아니라, 저장 후 피드백을 받는 속도와 대규모 모노레포의 개발 흐름에도 영향을 준다.

다만 “10배 빠르다”는 수치가 모든 프로젝트에서 같은 결과를 보장하지는 않는다. 사용 중인 프레임워크 플러그인, 템플릿 안의 타입 검사, CI 캐시, 에디터 확장이 도구 체인에 섞여 있기 때문이다. 이번 릴리스는 속도 자체보다도, 타입 검사와 언어 서버를 운영 환경처럼 측정하고 호환성을 분리해 보는 계기로 읽을 만하다.

## 핵심 내용

### JavaScript 구현에서 Go 네이티브 구현으로

TypeScript 팀은 기존 TypeScript 코드베이스의 구조와 타입 검사 논리를 최대한 유지한 채, 컴파일러와 언어 서비스를 Go로 포팅했다. 목적은 언어 규칙을 새로 설계하는 것이 아니라 네이티브 코드 속도와 공유 메모리 멀티스레딩을 활용하는 데 있다. 공식 발표는 전체 빌드에서 보통 8~12배의 향상을 언급한다.

이 변화에서 중요한 구분은 **언어 호환성**과 **도구 구현**이다. 타입 규칙이 갑자기 다른 언어가 되는 것은 아니지만, 같은 규칙을 더 빠르게 계산하고 편집기 요청을 더 안정적으로 처리하는 기반이 바뀌었다. 프로젝트는 “타입 오류가 같게 나오는가”와 “검사 시간이 실제로 줄었는가”를 따로 확인해야 한다.

### `--watch`와 편집기 피드백의 변화

TypeScript 7은 `--watch` 모드도 새로 구성했다. 파일 변경 감지는 운영체제·파일 시스템·대형 `node_modules` 구조의 영향을 크게 받는다. 단순 주기적 폴링은 많은 파일을 가진 프로젝트에서 CPU 사용량을 높일 수 있는데, 새 구현은 Parcel 파일 감시기의 기반을 Go로 이식해 플랫폼별 파일 변경 감시를 더 안정적으로 다루려 한다.

개발자가 체감하는 변화는 저장 후 타입 오류가 표시되기까지의 시간, 편집기 자동 완성·정의 이동의 응답성, 변경이 잦은 브랜치에서의 CI 대기 시간으로 나타날 수 있다. 이때 에디터가 실제로 TypeScript 7 언어 서버를 사용하고 있는지, 빌드 도구가 다른 TypeScript 버전을 고정하고 있지는 않은지를 함께 확인해야 한다.

### 전환 전에 볼 호환성 경계

공식 발표에 따르면 TypeScript 7은 TypeScript 6의 타입 검사와 명령줄 동작을 호환하는 방향으로 설계됐지만, 6에서 이미 예고된 변경도 함께 적용한다. 예를 들어 `strict` 기본값, `module`과 `target`의 기본값, 사용 중단된 플래그는 오래된 설정 파일에서 빌드 차이를 만들 수 있다. 따라서 5.x에서 곧바로 7로 옮기는 것보다 6의 변경을 먼저 이해하면 문제를 분리하기 쉽다.

또한 Vue·MDX·Astro·Svelte처럼 TypeScript를 다른 컴파일러나 템플릿 언어 안에 넣어 쓰는 도구는 안정적인 프로그램 API가 아직 제공되지 않는 경계를 가질 수 있다. 이런 프로젝트는 CLI의 빠른 `tsc` 검사와 편집기용 기존 언어 서버를 한동안 병행해야 할 수 있다. “표준 React·TypeScript 코드”와 “프레임워크가 덧붙인 언어 도구”를 같은 호환성 문제로 뭉뚱그리지 않는 것이 핵심이다.

## 개발자가 알아둘 변화

- **속도는 측정값으로 확인한다**: 로컬 전체 타입 검사, CI 타입 검사, `--watch`의 첫 실행과 증분 실행 시간을 나누어 비교한다.
- **버전 경로를 확인한다**: `package.json`, lockfile, CI 이미지, 에디터 확장이 같은 TypeScript 버전을 가리키는지 먼저 본다.
- **설정 변경을 독립적으로 다룬다**: `strict`, `module`, `target`, 사용 중단 플래그에서 나는 오류는 Go 포트 자체의 회귀와 구분한다.
- **프레임워크 도구는 별도 검증한다**: 템플릿 언어·언어 서버 플러그인·특수 변환기를 쓰는 경우에는 지원 상태와 우회 경로를 확인한 뒤 도입한다.

## 용어와 맥락

- **네이티브 포트**: 기존 도구의 동작을 유지하면서 다른 언어와 실행 방식으로 다시 구현하는 작업이다.
- **언어 서버(LSP)**: 편집기의 자동 완성, 오류 표시, 정의로 이동 같은 기능에 언어 분석 결과를 제공하는 프로세스다.
- **공유 메모리 멀티스레딩**: 여러 실행 단위가 같은 메모리 공간을 활용해 분석 작업을 병렬화할 수 있는 구조다.
- **증분 검사**: 전체 파일을 매번 다시 검사하지 않고, 변경된 파일과 영향 범위를 중심으로 다시 검사하는 방식이다.
- **임베디드 언어 도구**: Vue·MDX·Astro처럼 TypeScript가 템플릿·문서·다른 언어 처리 과정에 포함되는 도구를 말한다.
