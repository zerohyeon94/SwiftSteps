# 2026-08-12 - GuardDuty 런타임 민감 파일 변경 탐지

> Daily: [[2026-08-12]]
> 분류: IT Trends
> 영역: 클라우드·백엔드·데이터·보안·오픈소스
> 읽기 목표: 5-10분

## 한 줄 요약

AWS GuardDuty Runtime Monitoring은 EC2·EKS·ECS 워크로드에서 인증 설정·구성·로그처럼 민감한 파일의 변경을 탐지하는 세 가지 새 탐지 유형을 추가해, 컨테이너와 서버 침해 뒤의 지속성·권한 상승·흔적 삭제 징후를 런타임 신호로 다루게 했다.

## 왜 지금 볼 만한가

서버 보안은 배포 전 취약점 스캔만으로 끝나지 않는다. 공격자는 취약점을 이용해 들어온 뒤 설정 파일을 바꾸고, 계정을 추가하고, 로그나 심볼릭 링크를 조작해 접근을 유지하려 할 수 있다. Go API와 PostgreSQL을 Docker·Linux·Windows에서 다룰 때도 “이미지에 취약점이 있는가”와 “실행 중인 프로세스가 예상과 다른 파일 변경을 했는가”는 다른 질문이다.

이번 변화는 클라우드 보안 도구 하나를 도입하라는 뜻이 아니다. 런타임 관측을 설계할 때 `중요 파일 목록 → 허용되는 변경 주체 → 탐지 신호 → 실제 변경인지 조사하는 로그`라는 흐름을 분리해야 한다는 사례로 읽는 편이 유용하다.

## 핵심 내용

### 파일 변경 자체보다 변경의 맥락을 본다

AWS는 2026년 7월 GuardDuty Runtime Monitoring에 민감 파일 변경을 대상으로 한 세 탐지 유형을 추가했다고 발표했다. 이름은 `Persistence:Runtime/SensitiveFileModified`, `PrivilegeEscalation:Runtime/SensitiveFileModified`, `DefenseEvasion:Runtime/SensitiveFileModified`다. 각각 공격자가 지속 실행을 준비하거나, 더 높은 권한을 얻거나, 탐지를 피하려는 과정에서 보일 수 있는 파일 변경을 분류한다.

그러나 “파일이 바뀌었다”는 사실만으로 침해를 확정할 수는 없다. 정상 배포, 패키지 업데이트, 인증서 교체, 운영자가 수행한 설정 변경도 같은 종류의 파일 작업을 만들 수 있다. 탐지 결과는 경보의 시작점이며, 배포 시간·변경자·변경된 경로·컨테이너 이미지·프로세스·인증 로그를 함께 대조해야 한다.

### 다섯 파일 작업과 우회 방식

발표에 따르면 이 탐지는 쓰기 열기, 이름 변경, 심볼릭 링크 생성, 하드 링크 생성, 삭제의 다섯 작업을 직접 관찰한다. 단순히 셸 명령줄에서 특정 문자열을 찾는 방식보다, 우회된 실행 방식에서도 파일 수준의 행위를 포착하려는 접근이다.

예를 들어 공격자가 설정 파일을 새 내용으로 덮어쓰지 않고 임시 파일을 만든 뒤 이름을 바꾸거나, 정상 경로를 다른 파일로 가리키는 링크를 만들 수 있다. 이때 파일의 최종 내용만 비교하면 변경 과정과 의도를 놓칠 수 있다. 반대로 모든 파일 작업을 위험으로 처리하면 정상 운영 경보가 과도해진다. 따라서 민감 경로와 운영 변경 창을 정의하는 일이 먼저다.

### 컨테이너와 호스트의 책임은 다르다

컨테이너에서는 이미지가 불변에 가깝게 배포되는 구조를 지향하더라도, 마운트된 볼륨·환경 설정·노드의 파일 시스템 같은 변경 지점이 남는다. EC2에서는 애플리케이션 설정, 서비스 계정, 로그 경로와 운영자 접근 경로를 더 폭넓게 점검해야 할 수 있다. EKS·ECS·EC2라는 실행 기반이 다르면 누가 파일을 바꿨는지 확인하는 로그와 대응 절차도 달라진다.

Go 서비스 관점에서는 `.env`나 비밀값 파일을 Git에 넣지 않는 기본 원칙과 함께, 실행 중에 어떤 파일을 읽고 쓰는지 문서화하는 습관이 중요하다. 민감 파일을 너무 넓게 잡으면 경보가 소음이 되고, 너무 좁게 잡으면 지속성·권한 변경의 흔적을 놓칠 수 있다.

## 개발자가 알아둘 변화

- **배포 전과 실행 중을 분리한다**: SBOM·이미지 스캔은 배포 전 질문이고, 파일 변경 탐지는 런타임 질문이다.
- **허용 변경의 기준을 남긴다**: 배포 파이프라인, 운영자 계정, 유지보수 창, 변경 티켓을 로그와 연결해야 탐지의 조사 비용이 줄어든다.
- **경보는 증거와 함께 본다**: 경로·프로세스·컨테이너 이미지·IAM 또는 OS 계정·네트워크 연결을 묶어야 오탐과 실제 침해를 구분할 수 있다.
- **도구 지원 범위를 먼저 확인한다**: 이 기능의 지원 리전, 요금, 에이전트·런타임 요구사항, 보호 대상 파일 범위는 실제 도입 전에 AWS의 최신 문서에서 확인해야 한다.

## 용어와 맥락

- **런타임 모니터링**: 배포된 뒤 실행 중인 프로세스·파일·네트워크 행위를 관찰하는 보안 방식이다.
- **지속성(Persistence)**: 재시작 뒤에도 접근이나 악성 실행을 유지하려는 기법이다.
- **권한 상승(Privilege escalation)**: 더 넓은 시스템 권한을 얻으려는 행위다.
- **방어 회피(Defense evasion)**: 로그·설정·탐지 경로를 바꿔 보안 통제를 피하려는 행위다.
- **심볼릭 링크**: 다른 파일이나 디렉터리를 가리키는 파일 시스템 참조다. 정상 운영에도 쓰이지만 경로를 바꾸는 데 악용될 수 있다.
