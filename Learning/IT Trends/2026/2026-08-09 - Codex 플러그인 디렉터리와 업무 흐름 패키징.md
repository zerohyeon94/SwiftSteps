# 2026-08-09 - Codex 플러그인 디렉터리와 업무 흐름 패키징

## 한 줄 요약

Codex와 ChatGPT에서 플러그인 디렉터리가 앱 디렉터리를 대체하면서, 반복 업무는 단일 도구 연결이 아니라 `스킬 + 앱 + 설정 템플릿`을 묶은 작업 흐름 단위로 배포·관리하는 방향으로 바뀌고 있다.

## 왜 지금 볼 만한가

AI 코딩 도구는 모델에게 한 번 질문하는 도구에서, 저장소·문서·이슈·배포 도구를 오가며 여러 단계를 수행하는 작업 공간으로 바뀌고 있다. 이때 중요한 설계 단위는 "어떤 모델을 쓸까"뿐 아니라, 어떤 지침을 재사용하고 어떤 외부 시스템에 어떤 권한으로 연결할지를 함께 정하는 것이다.

## 핵심 내용

OpenAI는 2026년 7월 9일부터 기존 앱 디렉터리를 플러그인 디렉터리로 옮겼다. 플러그인은 특정 업무 흐름에 필요한 능력을 묶는 패키지로, 재사용 가능한 지침인 **스킬**, 외부 데이터와 작업에 연결되는 **앱**, 조직별 연결 설정을 돕는 **앱 템플릿**을 포함할 수 있다. 기존 앱 연결 자체가 사라진 것이 아니라, 더 큰 작업 흐름 안의 구성 요소가 된 셈이다.

이 변화는 에이전트 활용의 단위를 "도구 하나"에서 "업무 한 묶음"으로 옮긴다. 예를 들어 코드 리뷰 업무에는 리뷰 기준을 담은 스킬, GitHub 정보에 접근하는 앱, 조직의 승인·읽기 전용 정책이 함께 필요할 수 있다. 즉 기능 목록을 많이 붙이는 것보다, 입력 정보·행동 범위·검증 기준이 같은 업무에 맞게 조합됐는지가 더 중요하다.

플러그인이 보인다고 해서 모든 기능을 바로 실행할 수 있는 것도 아니다. 앱을 포함한 플러그인은 워크스페이스의 역할 설정, 앱 활성화 여부, OAuth 연결, 원본 시스템의 권한을 모두 만족해야 한다. 특히 민감한 저장소나 고객 데이터가 연결되는 업무라면 처음에는 읽기 전용 범위로 시작하고, 실제 쓰기 권한은 필요한 작업에만 별도로 열어 두는 편이 안전하다.

OpenAI가 소개한 역할별 플러그인은 데이터 분석·크리에이티브 제작·영업·제품 디자인처럼 서로 다른 업무에 필요한 앱과 스킬을 묶는 사례다. 개발자에게도 같은 관점이 유용하다. Daily Note 생성처럼 반복되는 개인 작업은 문서 구조·이월 판단·검증 규칙을 스킬로 고정하고, 외부 읽기 자료나 Notion 페이지는 필요한 범위에서만 연결하면 매일의 결과 품질을 일정하게 만들 수 있다.

## 개발자가 알아둘 변화

- **프롬프트를 반복해서 복사하는 방식의 한계**: 잘 작동하는 순서·검증 규칙·출력 형식은 스킬로 분리해야 변경과 재사용이 쉬워진다.
- **앱 연결은 권한 설계 문제**: 플러그인은 원본 시스템의 권한을 우회하지 않는다. 읽기·수정·전송 권한과 승인 단계를 업무별로 확인해야 한다.
- **도입 단위는 작은 반복 업무부터**: 예를 들어 PR 요약, 장애 기록 정리, Daily Note 준비처럼 입력과 완료 조건이 분명한 흐름부터 패키지화한 뒤 범위를 넓히는 편이 검증하기 쉽다.
- **스킬과 앱의 책임을 나눈다**: 스킬은 "어떻게 판단하고 결과를 만들지", 앱은 "어디서 읽고 무엇을 할지"를 담당하도록 구분하면 권한 변경과 지침 개선이 서로 얽히지 않는다.

## 용어와 맥락

- **플러그인**: 특정 작업 흐름에 필요한 스킬·앱·앱 템플릿을 묶은 배포 단위.
- **스킬**: 반복 가능한 지침, 예시, 워크플로를 담아 에이전트의 수행 방식을 일정하게 만드는 구성 요소.
- **앱**: 저장소, 문서, 데이터베이스처럼 외부 시스템의 데이터·행동에 연결하는 구성 요소.
- **앱 템플릿**: 조직이 필요한 앱 연결을 만들거나 설정할 때 쓰는 출발점. 설치된 플러그인만으로 자동 연결되지는 않는다.
- **최소 권한**: 업무에 필요한 범위만 접근·행동을 허용하는 원칙. 에이전트 연결에서도 읽기 전용과 승인 단계를 먼저 고려한다.
