# 2026-07-18 - Swift 6.3의 Android SDK 정식 출시

> Daily: [[2026-07-18]]
> 분류: IT Trends
> 읽기 목표: 5-10분

## 한 줄 요약

Swift 6.3은 Swift SDK for Android를 처음 공식 출시했다. Swift 패키지를 Android용으로 빌드하고 Kotlin·Java 앱과 JNI 경계에서 연동할 수 있지만, Android 네이티브 역량의 기본 축은 여전히 Kotlin과 Android 도구 체인이다.

## 왜 지금 볼 만한가

이번 주의 목표는 Swift와 Kotlin으로 같은 건강 목표 도메인 규칙을 각각 구현해 보는 것이다. Swift가 Android까지 확장되는 흐름은 “한 언어로 모든 앱을 만든다”는 결론보다, 공유할 규칙과 플랫폼별 UI·생태계 지식을 어떻게 구분할지를 생각할 좋은 사례다.

## 핵심 내용

### 1. Swift 6.3에서 Android SDK가 공식 출시됐다

Swift 6.3은 Android용 Swift SDK의 첫 공식 릴리스를 포함한다. Swift 패키지를 Android 대상으로 빌드하고, Swift Java 및 Swift Java JNI Core를 통해 기존 Kotlin·Java Android 앱과 연동할 수 있다.

### 2. 빌드에는 별도 도구 체인이 필요하다

공식 시작 문서는 호스트용 Swift 툴체인, Android용 Swift SDK, Android NDK를 각각 준비해 크로스 컴파일하는 방식을 안내한다. 즉 iOS용 Xcode 설정만으로 바로 Android 앱을 만드는 흐름은 아니다.

### 3. Kotlin을 대체한다는 뜻은 아니다

공식 문서는 Android 앱이 보통 Java 또는 Kotlin으로 작성되며, Swift 모듈은 공유 라이브러리로 포함해 JNI 경계에서 접근할 수 있다고 설명한다. 따라서 현재의 학습 우선순위는 Kotlin·Android 네이티브를 유지하고, Swift Android SDK는 공유 로직·상호운용성의 선택지로 이해하는 것이 적절하다.

## 내 학습/프로젝트와의 연결

- 오늘의 `HydrationGoal`에서 **컵 수와 목표 수 → 완료율** 계산은 두 플랫폼에서 같은 도메인 규칙이다.
- SwiftUI와 Jetpack Compose의 화면 상태·UI 계층은 플랫폼별로 따로 익혀야 한다.
- 장기적으로는 헬스케어 계산·검증 규칙처럼 테스트하기 쉬운 부분을 공유 후보로 보고, 센서 권한·UI·플랫폼 API는 각 네이티브 계층의 책임으로 설명하는 포트폴리오가 된다.
