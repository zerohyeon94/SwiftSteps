# 2026-07-17 - Kotlin 2.4.0의 Swift 패키지 의존성과 Swift export

> Daily: [[2026-07-17]]
> 분류: IT Trends
> 읽기 목표: 5-10분

## 한 줄 요약

Kotlin 2.4.0은 Kotlin Multiplatform(KMP) 모듈에서 Swift Package 의존성을 쓰는 흐름과 Swift export를 보강했다. 다만 Swift export는 아직 Alpha이므로, 두 플랫폼의 경계를 없애기보다 어떤 코드와 타입을 공유할지 검증하는 관점으로 봐야 한다.

## 왜 지금 볼 만한가

오늘 Day 2는 `Int`·`Double`의 추론과 변환 시점을 다룬다. iOS와 Android를 모두 고려하는 모바일 엔지니어에게 타입은 한 언어 안의 문법 문제가 아니라, API·공유 모듈·화면 모델 경계를 넘을 때 의미와 정밀도를 보존하는 설계 문제이기도 하다.

KMP가 Swift와 더 자연스럽게 연결되는 방향은 흥미롭지만, 현재 목표는 KMP를 바로 도입하는 것이 아니다. Swift와 Kotlin을 각각 정확히 읽고, 나중에 공유 경계를 만들 때 무엇을 확인해야 하는지 한 번 알아두는 데 있다.

## 핵심 내용

- Kotlin 2.4.0은 Kotlin/Native에서 Swift Package 의존성을 가져오는 기능과 Swift export 개선을 주요 항목으로 소개한다. 따라서 Apple 플랫폼 전용 라이브러리가 필요한 KMP 모듈에서도 의존성 경계를 더 명시적으로 관리할 수 있다.
- Swift export는 Kotlin 소스를 Objective-C 헤더를 거치지 않고 Swift 인터페이스로 내보내는 기능이다. 공식 문서 기준으로 `suspend` 함수는 Swift의 `async`로, `kotlinx.coroutines`의 `Flow`는 `AsyncSequence`로 연결할 수 있다.
- 타입 경계는 여전히 확인 대상이다. Swift export 문서의 현재 매핑에서 Kotlin `Int`는 `Swift.Int32`, `Long`은 `Int64`, `Double`은 `Double`로 표현된다. 걸음 수 같은 정수와 달성률 같은 소수 비율의 의미를 공유 코드의 이름·타입·변환 지점에 남겨야 하는 이유다.
- Swift export는 Alpha이며, 현재는 직접 Xcode 통합 방식에서만 동작하고 제네릭 타입 소거, 컬렉션 상속, 언어 간 상속 등 제약이 있다. 새 포트폴리오의 기본 구조로 즉시 고정하기보다 작은 공유 모듈에서 빌드·API 표면·Xcode 통합을 확인한 뒤 판단하는 편이 안전하다.

## 내 학습/프로젝트와의 연결

- Day 2에서 `Int / Int`를 먼저 계산한 뒤 `Double`로 바꾸면 `0.0`이 되는 이유를 설명해 본다. 이때 변환은 화면에 표시하기 직전이 아니라 데이터의 의미가 바뀌는 경계에 둔다는 원칙을 함께 기억한다.
- 이후 iOS·Android에 같은 건강 데이터 기능을 구현할 때는 “공유할 도메인 규칙”과 “각 플랫폼 UI에 남길 표현”을 나눠 적는다. KMP는 그 선택을 돕는 도구이지, Swift와 Kotlin의 기본기를 대신하지 않는다.
- 주말 실습에서는 Swift와 Kotlin으로 동일한 달성률 계산을 직접 실행해 본 뒤, 공유 모듈이 생긴다면 입력 정수·출력 비율·0으로 나누기 규칙을 어떤 계약으로 둘지 한 줄 메모를 남긴다.
