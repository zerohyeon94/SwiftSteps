# 2026-08-29 - Go 1.27의 제네릭 메서드와 JSON v2

> Daily: [[2026-08-29]]
> 분류: IT Trends
> 영역: 프로그래밍 언어·런타임·프레임워크
> 읽기 목표: 5-10분

## 한 줄 요약

Go 1.27은 구체 타입(concrete type)의 제네릭 메서드를 도입하고 `encoding/json/v2`를 포함해, 재사용 가능한 API의 표현력과 JSON 처리의 기본 동작을 함께 확장했다.

## 왜 지금 볼 만한가

Go 서비스 코드에서 제네릭을 쓰는 범위가 넓어졌지만, 인터페이스 메서드까지 제네릭화된 것은 아니다. 이 경계를 알아야 기존 인터페이스 계약을 잘못 가정하지 않고, JSON v2의 더 엄격한 동작도 실제 테스트 결과로 점검할 수 있다.

## 핵심 내용

### 1. 구체 타입의 제네릭 메서드

Go 1.27부터 제네릭 타입의 메서드가 자체 타입 매개변수를 가질 수 있다. 예를 들어 컨테이너가 담은 값을 다른 타입으로 변환하는 `Map[R any]` 같은 메서드를 표현할 수 있다. 이전에는 같은 표현을 독립 함수로 두거나 반환 타입을 미리 고정하는 설계가 흔했다.

다만 이 기능은 **구체 타입의 메서드**에 한정된다. Go 공식 설명은 제네릭 메서드를 인터페이스에 선언하는 것은 여전히 지원하지 않는다고 밝힌다. 따라서 “어떤 타입에 제네릭 메서드가 있다”는 사실만으로 그 타입이 기존의 비제네릭 인터페이스를 구현한다고 단정할 수 없다.

### 2. JSON v2와 호환성 판단

Go 1.27 릴리스 노트는 `encoding/json/v2`와 `encoding/json/jsontext`를 추가했다. 새 API는 JSON 처리의 더 엄격한 기본값과 옵션 선택을 제공하며, 기존 `encoding/json`도 내부적으로 v2 구현을 활용한다. 그렇다고 기존 서비스의 요청·응답 계약을 자동으로 바꿔도 된다는 의미는 아니다.

API 서버는 아래를 구분해 확인할 필요가 있다.

- 새 v2 API를 직접 채택할지, 기존 API를 유지할지
- 알 수 없는 필드·중복 이름·문법 오류가 현재 클라이언트와 어떻게 맞물리는지
- 디코딩 실패를 HTTP 400으로 변환하는 현재 오류 응답 형식이 유지되는지

### 3. 개발자가 알아둘 변화

업그레이드 판단의 첫 단계는 “새 문법을 즉시 적용할까”가 아니라 현재 모듈과 테스트에서 어떤 동작이 달라지는지 확인하는 일이다. 제네릭 메서드는 컨테이너형 API가 정말 타입 매개변수를 추가로 필요로 할 때 검토하고, 인터페이스 경계를 넘는 공통 동작은 기존처럼 비제네릭 계약 또는 독립 함수로 설계할 수 있다.

이 Daily 읽기는 개념 파악용이다. 실제 Go 버전 교체, 코드 수정, 명령 실행은 별도 구현 작업에서 범위와 테스트를 정한 뒤 진행한다.

그림은 Go 1.27에서 가능한 구체 타입의 제네릭 메서드와, 아직 허용되지 않는 제네릭 인터페이스 메서드를 구분한다. 실제 타입 검사 규칙 전체가 아니라 설계 시 먼저 확인할 경계를 요약한 개념도다.

## 용어와 맥락

- **제네릭 메서드**: 타입 자체의 매개변수와 별도로 메서드가 타입 매개변수를 받는 메서드다.
- **구체 타입**: 여기서는 실제 타입 정의에 붙는 메서드의 수신 타입을 가리킨다.
- **인터페이스 계약**: 구현체가 제공해야 하는 메서드 집합이다. Go 1.27에서도 인터페이스에 제네릭 메서드를 선언할 수는 없다.
- **엄격한 기본값**: 입력을 더 넓게 받아들이기보다 문제 있는 JSON을 명확히 드러내도록 하는 처리 방향이다.
