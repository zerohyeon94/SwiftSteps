# 2026-07-23 - Android 17의 적응형 UI와 화면 제약 해제

> Daily: [[2026-07-23]]
> 분류: IT Trends
> 읽기 목표: 5-10분
> 자료 기준일: 2026-07-23

## 한 줄 요약

Android 17(API 37)은 큰 화면에서 화면 회전·창 크기·가로세로 비율을 앱이 고정하려는 제약을 무시하는 방향으로 전환해, Android 앱의 기본 전제를 “세로 스마트폰 화면”에서 **어떤 창 크기에도 적응하는 UI**로 바꾼다.

## 왜 지금 볼 만한가

태블릿·폴더블·데스크톱 창 모드가 일반화되면 `screenOrientation="portrait"`나 고정 비율은 레이아웃을 지키는 안전장치가 아니라 UI 결함을 숨기는 임시 방편이 될 수 있다. Android 17을 타깃으로 하는 앱은 큰 화면에서 이런 제약이 더 이상 기대대로 작동하지 않으므로, 화면 상태와 레이아웃 구조를 분리해 검증해야 한다.

## 핵심 내용

### 무엇이 달라지는가

Android 17(API 37) 이상을 타깃으로 하는 앱은 최소 너비가 600dp를 초과하는 화면에서 방향, 크기 조절, 화면 비율 제한이 적용되지 않는다. 앱은 사용자가 만든 창 전체를 채우며, 고정 비율 때문에 생기던 pillarbox도 사용하지 않는다. Android는 이를 여러 기기·창 모드에 적응하는 플랫폼 기본 동작으로 설명한다.

영향을 받는 대표 항목은 매니페스트의 `screenOrientation`, `resizableActivity`, `minAspectRatio`, `maxAspectRatio`와 런타임의 `setRequestedOrientation()`·`getRequestedOrientation()`이다. 즉 “세로 전용으로 잠갔으니 레이아웃도 세로로만 온다”는 가정이 큰 화면에서는 성립하지 않는다.

이 규칙은 모든 화면과 기기에 무조건 적용되는 것이 아니다. 게임, 사용자가 기기 설정에서 앱의 기본 비율 동작을 명시적으로 선택한 경우, 최소 너비가 `sw600dp`보다 작은 화면에는 예외가 있다. 따라서 휴대전화만 한 번 실행해 보고 안전하다고 판단하면 안 된다.

### 왜 레이아웃 문제로 이어지는가

세로 고정 화면만 기준으로 만든 UI는 넓은 창에서 빈 공간이 과도하게 생기거나, 가로 방향에서 버튼과 입력 필드가 잘리고, 고정 크기 애니메이션이 화면 밖으로 나갈 수 있다. 카메라 미리보기처럼 센서 방향·화면 방향·창 비율을 같은 것으로 가정한 코드도 늘어짐, 회전, 잘림을 보일 수 있다.

회전과 창 크기 변화가 늘면 Activity 재생성도 더 자주 관찰된다. 화면에 보이던 필터, 스크롤 위치, 입력 중인 값, 로딩·성공·실패 상태를 화면 회전에 묶어 두지 않고 `ViewModel`과 저장 가능한 UI 상태로 나눠야 하는 이유다. 이는 SwiftUI의 상태가 View 재생성 뒤에도 어떤 소유자에 남는지 점검하는 문제와도 닮아 있다.

## 개발자가 알아둘 변화

- **창 크기를 입력값으로 본다.** 화면 폭을 하나의 상수로 가정하지 말고, 폭·높이·접힘 상태에 따라 한 열/두 열, 목록/상세 동시 표시처럼 구조를 바꾼다.
- **고정 방향 요청을 조사한다.** 매니페스트와 `setRequestedOrientation()` 호출을 찾아, 사용성·카메라·게임성처럼 정말 필요한 이유가 있는지 구분한다.
- **상태 보존을 먼저 확인한다.** 회전·멀티윈도우·폴더블 전환 뒤에도 검색어, 선택 항목, 네트워크 상태가 유지되는지 점검한다. 레이아웃만 맞아도 상태가 사라지면 적응형 경험은 실패한다.
- **실기기와 창 모드에서 검증한다.** 에뮬레이터나 태블릿·폴더블에서 세로/가로, 분할 화면, 창 크기 변경을 반복해 본다. Android는 `UNIVERSAL_RESIZABLE_BY_DEFAULT` 호환성 플래그로 이 동작을 미리 시험할 방법도 제공한다.

## 용어와 맥락

- **적응형(adaptive) UI**: 기기 이름이 아니라 실제 창의 크기·방향·접힘 상태에 맞춰 정보 구조와 배치를 바꾸는 UI 설계다.
- **`sw600dp`**: 화면의 더 짧은 변 길이를 기준으로 하는 Android 리소스 한정자다. 보통 큰 화면 레이아웃을 나누는 기준으로 쓰이지만, 기기 모델을 판별하는 값은 아니다.
- **Pillarbox**: 앱의 비율을 유지하려고 좌우 또는 상하에 띠 모양 여백을 넣는 표시 방식이다.
- **상태 보존**: 구성 변경 뒤에도 사용자가 보던 화면의 의미 있는 상태를 복원하는 일이다. ViewModel, `SavedStateHandle`, Compose의 상태 보존 도구 등이 이 문제를 다룬다.
