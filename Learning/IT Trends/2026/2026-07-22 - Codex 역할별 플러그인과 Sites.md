# 2026-07-22 - Codex 역할별 플러그인과 Sites

> Daily: [[2026-07-22]]
> 분류: IT Trends
> 읽기 목표: 5-10분

## 한 줄 요약

OpenAI가 역할별 플러그인, 공유 가능한 Sites, 선택 영역을 바로 고치는 주석 기능을 공개하면서, AI 코딩 에이전트의 핵심이 단순한 코드 생성에서 **팀 도구·업무 맥락·검토 흐름을 연결하는 것**으로 넓어지고 있다.

## 왜 지금 볼 만한가

개발자는 이제 모델 성능만 비교하는 대신, 에이전트가 어떤 외부 도구에 접근하는지, 반복 작업을 어디까지 자동화하는지, 사람이 어떤 지점에서 결과를 검토·수정하는지를 함께 설계해야 한다. 역할별 플러그인은 앱 연결, 스킬, 지침, 워크플로를 한 단위로 묶고, Sites와 주석은 결과물을 팀이 공유하고 다듬는 다음 단계를 겨냥한다.

## 핵심 내용

- **역할별 플러그인**은 특정 업무에 필요한 앱 연결, 스킬, 지침, 워크플로를 묶어 제공한다. 같은 모델이라도 저장소 규칙, 문서·티켓·메신저 연결, 승인 기준이 다르면 실제 업무 방식이 달라진다는 점을 보여 준다.
- **Sites**는 에이전트가 만든 대시보드·계획 도구·검토 화면 같은 인터랙티브 결과물을 워크스페이스 안에서 URL로 공유하는 기능이다. 발표용 산출물이 아니라, 팀이 같은 상태를 보고 의견을 남기는 작업 공간으로 활용하는 흐름에 가깝다.
- **주석(annotations)**은 코드·문서·웹 화면의 특정 부분을 가리켜 수정을 요청하는 방식이다. 전체 프롬프트를 다시 쓰기보다 수정 범위를 좁히므로, 결과물을 검토하고 피드백하는 비용을 줄일 수 있다.
- 이 변화가 “에이전트가 알아서 모든 일을 한다”는 뜻은 아니다. 연결된 앱의 권한, 민감 정보 노출 범위, 자동화가 바꿀 수 있는 대상, 최종 검토 책임을 먼저 정해야 한다.

## 개발자가 알아둘 변화

- AI 에이전트를 도입할 때는 모델 선택보다 먼저 **업무 경계**를 적는다. 예를 들어 “문서 초안은 생성 가능, 고객 데이터 변경과 배포는 사람 승인 후”처럼 행동별 권한을 나눈다.
- 플러그인은 재사용 가능한 팀 작업 규칙의 배포 단위가 될 수 있다. 프로젝트의 `AGENTS.md`, 스킬, 연결 앱 권한을 함께 점검해야 플러그인이 일관된 결과를 낸다.
- 공유 가능한 산출물이 늘수록 코드 리뷰뿐 아니라 문서·대시보드·학습 자료에도 변경 이력과 검토 기준이 필요하다. 주석은 사람의 판단을 없애는 기능이 아니라, 판단을 정확한 위치에 남기는 인터페이스다.

## 용어와 맥락

- **플러그인**: 특정 역할이나 업무 흐름에 맞게 앱 연결, 스킬, 지침을 패키징한 확장 단위다.
- **Sites**: 에이전트가 만든 인터랙티브 웹 결과물을 워크스페이스에서 공유하는 기능이다.
- **주석(Annotation)**: 결과물의 정확한 일부를 선택해 수정 의견이나 요청을 연결하는 방식이다.
- **권한 경계**: 에이전트가 읽기·작성·외부 전송·배포 같은 행동을 어디까지 할 수 있는지 정한 규칙이다.
