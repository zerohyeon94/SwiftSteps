# 2026-07-21 - Kotlin 2.4.0의 Swift 패키지 의존성과 Swift export

> Daily: [[2026-07-21]]
> 분류: IT Trends
> 읽기 목표: 5-10분

## 한 줄 요약

Kotlin 2.4.0은 Kotlin/Native에서 Swift 패키지 의존성과 Swift export를 보강해 iOS 연동의 선택지를 넓혔지만, 공유 코드의 경계를 잘 정하는 일이 여전히 핵심이다.

## 왜 지금 볼 만한가

프로그래밍 언어와 패키지 생태계의 경계가 점점 느슨해지고 있다. Kotlin/Native가 Swift 패키지를 직접 활용하고 Swift 쪽으로 API를 내보내는 기능을 강화했다는 것은, 멀티플랫폼 개발 도구가 단순한 코드 공유를 넘어 언어 생태계 사이의 연결을 넓히고 있다는 신호다.

## 핵심 내용

- Kotlin 2.4.0은 Kotlin/Native에서 **Swift 패키지를 의존성으로 사용하는 지원**과 **Swift export 업데이트**를 포함한다.
- 이 변화는 Kotlin Multiplatform에서 iOS 쪽 라이브러리·도메인 계층과 연결할 때 선택지를 늘린다. 다만 Swift export가 모든 Kotlin API를 아무 제약 없이 Swift에 자연스럽게 보이게 한다는 뜻은 아니다.
- 실제 프로젝트에서는 공유 후보를 순수 도메인 규칙, 계산, 네트워크 모델처럼 플랫폼과 독립적인 영역으로 제한하고, SwiftUI·Compose UI, 권한, SDK 연동, 빌드·릴리스는 각 플랫폼 경계에 남기는 편이 안전하다.
- 버전 업그레이드는 기능 사용보다 먼저 Gradle, Android Studio, 의존성 플러그인의 호환성을 확인하고 작은 모듈에서 빌드·테스트로 검증한다.

## 개발자가 알아둘 변화

- 멀티플랫폼 도구를 평가할 때는 "코드를 얼마나 공유하는가"뿐 아니라 언어 간 API가 얼마나 자연스럽게 노출되는지 살펴봐야 한다.
- 새 상호운용 기능이 추가되어도 빌드 도구, 디버깅, 플랫폼 SDK, 배포 파이프라인의 차이는 남는다.
- 기능 발표 직후에는 지원되는 타입, 제네릭, 예외 처리, 패키지 구조 같은 제한 사항과 도구 체인 호환성을 함께 확인해야 한다.

## 용어와 맥락

- **Kotlin/Native**: Kotlin 코드를 JVM 없이 네이티브 바이너리로 컴파일하는 기술이다.
- **Swift Package**: Apple 생태계에서 Swift 코드와 리소스를 배포하는 패키지 단위다.
- **Swift export**: Kotlin 선언을 Swift에서 사용할 수 있는 형태로 노출하는 상호운용 기능이다.
