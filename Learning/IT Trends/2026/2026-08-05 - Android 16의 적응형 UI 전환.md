# 2026-08-05 - Android 16의 적응형 UI 전환

> Daily: [[2026-08-05]]
> 분류: IT Trends
> 영역: 모바일 플랫폼·On-device AI
> 읽기 목표: 5-10분

## 한 줄 요약

Android 16(API 36)을 대상으로 하면 600dp 이상 화면에서 방향·화면비·크기 고정이 더 이상 레이아웃을 지켜 주지 않으므로, 적응형 UI·inset 처리·뒤로 가기 동작을 실제 창 크기 기준으로 검증해야 한다.

## 왜 지금 볼 만한가

Google Play는 2026년 8월부터 Android 16(API 36) 타기팅을 요구한다. 이는 단순한 `targetSdk` 숫자 갱신이 아니라, 태블릿·폴더블·데스크톱 창에서 앱이 항상 세로형 전화기처럼 보인다는 가정이 깨지는 전환점이다. iOS를 기반으로 Android까지 확장할 때도 화면 크기와 창 상태를 입력값으로 보는 설계 감각이 중요해진다.

## 핵심 내용

### 큰 화면에서는 고정 제약이 무시된다

Android 16을 target하면 `sw600dp` 이상 디스플레이에서 `screenOrientation`, `resizeableActivity`, `minAspectRatio`, `maxAspectRatio` 같은 방향·창 크기·화면비 제한이 기본적으로 적용되지 않는다. 앱은 태블릿, 폴더블의 안쪽 화면, 데스크톱 창처럼 넓은 환경에서 주어진 창을 채워야 한다.

기존에 세로 화면을 전제로 만든 레이아웃은 긴 행, 과도하게 넓어진 버튼, 화면 밖으로 밀려난 동작 버튼, 늘어나거나 잘린 카메라 미리보기 같은 문제를 낼 수 있다. 임시 호환성 opt-out은 가능하지만 API 37부터는 사라질 예정이므로, 유지 전략이 아니라 마이그레이션 시간을 확보하는 장치로만 보는 편이 맞다.

### Edge-to-edge와 뒤로 가기도 함께 점검한다

Android 16 기기에서 API 36을 target하는 앱은 edge-to-edge를 끌 수 없다. 상태 표시줄·내비게이션 바 영역까지 콘텐츠가 확장되는 만큼, Compose의 window inset 또는 View의 inset 처리가 중복되거나 빠지지 않았는지 확인해야 한다.

예측 뒤로 가기(predictive back) 시스템 애니메이션도 기본 활성화된다. 기존 `onBackPressed`나 `KEYCODE_BACK` 가로채기에 의존한 화면은 지원 API로 옮기고, 화면 전환·다이얼로그·웹 콘텐츠가 뒤로 가기 제스처와 어떤 순서로 반응하는지 실제 기기와 에뮬레이터에서 확인해야 한다.

### 적응형 UI는 화면 종류가 아니라 창 크기로 설계한다

Android 공식 가이드는 전화기·태블릿이라는 기기 이름보다 현재 창의 크기와 형태를 기준으로 레이아웃을 바꾸도록 권한다. 넓은 창에서는 목록과 상세를 두 패널로 나누고, 좁은 창에서는 한 화면 흐름으로 유지하는 식이다. 단순히 모든 컴포넌트를 가로 폭에 맞춰 늘리기보다 콘텐츠 최대 폭, 읽기 쉬운 행 길이, 스크롤 가능 여부, 키보드·마우스·스타일러스 입력을 함께 설계해야 한다.

## 개발자가 알아둘 변화

1. 매니페스트와 런타임에서 방향·화면비를 고정한 지점을 먼저 찾는다.
2. Android 16을 target한 상태로 태블릿·폴더블·가변 크기 창 에뮬레이터에서 핵심 흐름을 확인한다.
3. 넓은 창의 최대 콘텐츠 폭, 두 패널 전환, 스크롤, inset, 상태 복원을 점검한다.
4. 뒤로 가기·키보드·마우스 조작과 접근성 포커스 순서까지 테스트 범위에 넣는다.
5. 임시 opt-out을 쓴다면 이유와 제거 시점을 기록해 API 37 이전에 없앤다.

이 변화는 기존 화면을 Compose로 다시 쓰라는 요구가 아니다. View 기반 화면도 현재 창 크기와 inset을 기준으로 동작할 수 있어야 하며, Compose를 도입한다면 Material 3 Adaptive와 창 크기 클래스가 설계 의도를 드러내는 도구가 될 수 있다.

## 용어와 맥락

- **`sw600dp`**: 디스플레이의 최소 너비가 600dp 이상인 조건으로, 태블릿·대형 폴더블 내부 화면·데스크톱 창을 판단하는 기준에 쓰인다.
- **Edge-to-edge**: 시스템 바 뒤까지 콘텐츠를 확장하고 inset으로 안전 영역을 처리하는 UI 방식이다.
- **적응형 UI**: 기기 이름이 아니라 실제 창 크기·방향·입력 방식에 따라 정보 구조와 레이아웃을 조정하는 방식이다.
- **Predictive back**: 뒤로 가기 결과를 제스처 진행 중에 미리 보여 주는 시스템 동작으로, 앱의 탐색 상태와 충돌하지 않게 통합해야 한다.
