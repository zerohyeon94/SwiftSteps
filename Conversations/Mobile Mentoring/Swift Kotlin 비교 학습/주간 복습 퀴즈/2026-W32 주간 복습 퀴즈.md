## 문제 1~2. 개념 설명 선택

> 각 문제는 단일 선택이다.

### 문제 1 — 상수와 변수

- [ ] A. Swift의 `let`과 Kotlin의 `val`은 참조 대상의 모든 내부 상태를 언제나 바꾸지 못하게 한다.
- [ ] B. Swift의 `var`과 Kotlin의 `var`은 값 타입과 참조 타입의 동작이 완전히 같다.
- [ ] C. Swift `let`과 Kotlin `val`은 모두 바인딩 재할당을 막지만, 내부 상태의 변경 가능성은 타입·프로퍼티 가변성까지 봐야 한다.
- [ ] D. Kotlin의 `val`은 `var` 프로퍼티를 가진 객체를 선언할 수 없다.

### 문제 2 — 타입 추론과 비율

- [ ] A. `Int / Int`의 결과를 `Double(...)`로 감싸면, 나누기 전에 자동으로 실수 계산으로 바뀐다.
- [ ] B. Swift와 Kotlin은 정수와 실수를 언제나 자동 변환해 섞어 계산한다.
- [ ] C. 비율을 만들 때는 Swift에서 `Double(completed) / Double(total)`, Kotlin에서 `completed.toDouble() / total`처럼 나누기 전에 변환한다.
- [ ] D. 타입 추론은 실행 중 값에 따라 같은 변수의 타입을 바꾸는 기능이다.

<details>
<summary>문제 1~2 정답과 해설</summary>

- 문제 1 정답: C. 두 키워드는 바인딩의 재할당을 막는다. Swift 값 타입을 `let`으로 잡으면 가변 프로퍼티 변경도 막히지만, Kotlin의 `val` 객체는 내부 `var` 프로퍼티를 바꿀 수 있다.
- 문제 2 정답: C. `Int / Int`가 먼저 수행되면 정수 결과가 만들어진다. 소수 비율이 필요하면 나누기 연산 전에 적어도 한 피연산자를 실수로 변환해야 한다.

</details>

## 문제 3~4. 코드 실행 결과 선택

> 각 문제는 단일 선택이다.

### 문제 3 — Swift Optional

```swift
let nickname: String? = nil
print(nickname?.uppercased() ?? "GUEST")
```

- [ ] A. `nil`
- [ ] B. `GUEST`
- [ ] C. 컴파일 오류
- [ ] D. 런타임 오류

### 문제 4 — Kotlin 함수와 기본값

```kotlin
fun progress(steps: Int, goal: Int = 8_000): Int {
    return (steps.toDouble() / goal * 100).toInt()
}

println(progress(steps = 4_000))
```

- [ ] A. `0`
- [ ] B. `50`
- [ ] C. 기본값을 생략해서 컴파일 오류
- [ ] D. named argument는 기본값과 함께 쓸 수 없어서 컴파일 오류

<details>
<summary>문제 3~4 정답과 해설</summary>

- 문제 3 정답: B. 안전 호출은 `nil`에서 `nil`을 만들고, `??`가 기본 문자열 `GUEST`를 선택한다.
- 문제 4 정답: B. `goal`에는 기본값 8,000이 적용되고, `steps.toDouble()`이 정수 나눗셈을 막아 50을 만든다.

</details>

## 문제 5~6. 올바른 코드 또는 오류 코드 선택

### 문제 5 — 범위를 벗어나는 Swift 코드

> 단일 선택: `items`의 모든 원소와 인덱스를 출력하려 할 때, 마지막 반복에서 범위를 벗어나는 코드를 고른다.

### A

```swift
for index in items.indices {
    print(index, items[index])
}
```

- [ ] A 선택

### B

```swift
for (index, item) in items.enumerated() {
    print(index, item)
}
```

- [ ] B 선택

### C

```swift
for index in 0...items.count {
    print(index, items[index])
}
```

- [ ] C 선택

### D

```swift
for item in items {
    print(item)
}
```

- [ ] D 선택

### 문제 6 — 반환값이 필요한 Kotlin 함수

> 단일 선택: 호출한 화면에서 재사용할 달성률 문자열을 올바르게 반환하는 코드를 고른다.

### A

```kotlin
fun progressText(steps: Int, goal: Int) {
    "${steps / goal}%"
}
```

- [ ] A 선택

### B

```kotlin
fun progressText(steps: Int, goal: Int): String {
    return "${(steps.toDouble() / goal * 100).toInt()}%"
}
```

- [ ] B 선택

### C

```kotlin
fun progressText(steps: Int, goal: Int): String {
    println("${steps / goal}%")
}
```

- [ ] C 선택

### D

```kotlin
fun progressText(steps: Int, goal: Int): String {
    return steps / goal
}
```

- [ ] D 선택

<details>
<summary>문제 5~6 정답과 해설</summary>

- 문제 5 정답: C. `...`는 끝값을 포함하므로 `items.count` 인덱스까지 접근하게 된다. 유효한 마지막 인덱스는 `items.count - 1`이며 `items.indices`가 이를 안전하게 표현한다.
- 문제 6 정답: B. 실수 변환 뒤 퍼센트를 계산하고 `String`으로 반환해 호출한 쪽에서 값을 사용할 수 있다. A는 만든 문자열을 반환하지 않고, C는 `String` 반환이 없으며, D는 `Int`를 `String`으로 반환할 수 없다.

</details>

## 문제 7. Swift · Kotlin 차이

> 복수 선택 가능: 올바른 설명을 모두 고른다.

- [ ] A. Swift 값 타입을 `let`으로 선언하면 가변 프로퍼티 변경도 값 전체의 변경이므로 허용되지 않는다.
- [ ] B. Kotlin에서 `val profile = Profile(name = "Zero")`이고 `name`이 `var`이면 `profile.name`을 바꿀 수 있다.
- [ ] C. Swift의 `??`와 Kotlin의 `?:`는 값이 없을 때 기본값을 제공하는 데 사용할 수 있다.
- [ ] D. Swift `Int / Int`와 Kotlin `Int / Int`는 모두 자동으로 소수 비율을 만든다.

<details>
<summary>문제 7 정답과 해설</summary>

- 정답: A, B, C.
- 해설: Swift의 값 타입 상수는 내부 가변 프로퍼티도 바꿀 수 없지만, Kotlin의 `val`은 바인딩만 고정하므로 객체의 `var` 프로퍼티는 바꿀 수 있다. 두 언어 모두 null 가능 값의 기본값 문법을 제공한다. 정수 나눗셈은 양쪽 모두 정수 결과를 만든다.

</details>
