## 토요일 — 코드 작성·실행 60~90분

### 1. 메모 없이 개념 회상

- Swift에서 먼저 구현할 규칙: 값 타입의 프로퍼티 변경은 값 자체의 변경이므로 `var` 바인딩이 필요하다. 클래스는 `let` 참조라도 내부의 `var` 프로퍼티를 바꿀 수 있다.
- Kotlin에서 달라질 규칙: `val`은 재할당만 막는다. 참조 대상의 `var` 프로퍼티 변경은 가능하므로 모델의 프로퍼티와 컬렉션 가변성도 따로 설계한다.
- 실행 전 질문: 건강 목표 `cups`는 개수(`Int`)이고 완료율은 비율(`Double`)이다. 둘을 같은 타입으로 다뤄도 되는가?

### 2. Swift 작성·실행

아래를 직접 입력해 실행한다. 주석 처리된 두 오류 줄은 한 줄씩 주석을 풀어 컴파일 진단을 확인한 뒤 다시 주석 처리한다.

```swift
struct HydrationGoal {
    var cups: Int
    let target: Int

    mutating func recordCup() {
        cups += 1
    }

    var completion: Double {
        Double(cups) / Double(target)
    }
}

var today = HydrationGoal(cups: 6, target: 8)
today.recordCup()
print(today.cups)        // 7
print(today.completion)  // 0.875

let fixed = HydrationGoal(cups: 6, target: 8)
// fixed.recordCup()     // 오류: mutating member on immutable value

final class SyncSession {
    var retryCount = 0
}

let session = SyncSession()
session.retryCount += 1  // 가능: 참조는 유지하고 내부 상태만 변경
print(session.retryCount) // 1
// session = SyncSession() // 오류: let 바인딩 재할당
```

- 실행 명령 예시: `swiftc HealthProgress.swift -o HealthProgress && ./HealthProgress`
- 예상 결과: `7`, `0.875`, `1`이 순서대로 출력된다.

### 3. Kotlin 작성·실행

Swift와 같은 요구사항을 Kotlin으로 직접 입력해 실행한다. `goal` 재할당 줄의 주석을 풀어 Swift와 진단을 비교한다.

```kotlin
data class HydrationGoal(var cups: Int, val target: Int) {
    fun recordCup() {
        cups += 1
    }

    val completion: Double
        get() = cups.toDouble() / target
}

fun main() {
    val goal = HydrationGoal(cups = 6, target = 8)
    goal.recordCup()
    println(goal.cups)        // 7
    println(goal.completion)  // 0.875
    // goal = HydrationGoal(cups = 0, target = 8) // 오류: val 재할당

    val completed = 7
    val total = 10
    println(completed / total)              // 0
    println(completed.toDouble() / total)   // 0.7
}
```

- 실행 명령 예시: `kotlinc HealthProgress.kt -include-runtime -d HealthProgress.jar && java -jar HealthProgress.jar`
- 예상 결과: `7`, `0.875`, `0`, `0.7`이 순서대로 출력된다.

### 4. 두 언어 비교

| 관점 | Swift | Kotlin | 실무에서 기억할 기준 |
| --- | --- | --- | --- |
| 바인딩 | `let`은 재할당을 막고 값 타입의 변경도 막는다. | `val`은 재할당을 막지만 객체 내부 `var` 변경은 허용한다. | “불변”이라고 쓰기 전에 값/참조와 프로퍼티 가변성을 함께 확인한다. |
| 달성률 계산 | `Double(cups) / Double(target)`처럼 변환을 먼저 한다. | `cups.toDouble() / target`처럼 변환을 먼저 한다. | 개수와 비율의 변환은 ViewModel·UI 상태 경계 한 곳에 둔다. |
| 오류 진단 | `let` 값의 mutating 호출은 컴파일러가 막는다. | `val` 재할당은 막지만 내부 변경은 별도 모델 설계가 필요하다. | iOS·Android에서 같은 도메인 규칙을 구현해 차이를 설명할 수 있어야 한다. |
