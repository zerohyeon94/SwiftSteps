## 오늘의 학습 목표

- Swift의 `if`·`switch`와 Kotlin의 `if`·`when`을 문장과 표현식으로 사용하는 방식을 구분한다.
- 열거형 상태를 빠짐없이 분기하는 이유와 두 언어의 exhaustive 검사 방식을 설명한다.
- 값 순회와 인덱스 순회를 구분하고, 컬렉션 범위를 안전하게 표현하는 방법을 고른다.

## 1. 개념 읽기

### Swift에서 알아둘 점

- `if`는 조건에 따라 실행 흐름을 나누며, `else`를 포함한 `if` 표현식은 값을 만들어 대입할 수도 있다.
- `switch`도 문장뿐 아니라 표현식으로 사용할 수 있다. `enum`을 분기할 때는 모든 case를 다루거나 `default`를 둬야 하므로 새 상태가 추가됐는데 분기가 빠진 상황을 컴파일 단계에서 발견하기 좋다.
- 값만 필요하면 `for item in items`, 인덱스가 필요하면 `for index in items.indices`가 의도를 가장 잘 드러낸다. `Array`에서는 `0..<items.count`도 `0`부터 `count` 직전까지 순회한다.

```swift
enum SyncState {
    case idle, syncing, failed
}

let state = SyncState.syncing
let message = switch state {
case .idle:
    "준비됨"
case .syncing:
    "동기화 중"
case .failed:
    "다시 시도"
}

let steps = [1200, 1800, 2200]
for index in steps.indices {
    print(steps[index])
}
```

### Kotlin에서 알아둘 점

- Kotlin의 `if`와 `when`도 실행 흐름을 나누거나 값을 만드는 표현식으로 사용할 수 있다. `if`를 값으로 쓸 때는 결과가 없는 경우가 생기지 않도록 `else`가 필요하다.
- `enum class`나 `sealed` 계층을 `when` 표현식으로 빠짐없이 다루면 `else`를 생략할 수 있다. 일반 값의 일부만 분기하는 `when` 표현식은 보통 `else`로 나머지를 처리해야 한다.
- 값만 필요하면 `for (item in items)`, 인덱스가 필요하면 `for (index in items.indices)`가 명확하다. `0 until items.size`와 `0..<items.size`도 마지막 값인 `size`를 제외한다.

```kotlin
enum class SyncState { IDLE, SYNCING, FAILED }

val state = SyncState.SYNCING
val message = when (state) {
    SyncState.IDLE -> "준비됨"
    SyncState.SYNCING -> "동기화 중"
    SyncState.FAILED -> "다시 시도"
}

val steps = listOf(1200, 1800, 2200)
for (index in steps.indices) {
    println(steps[index])
}
```

### 두 언어의 핵심 차이

- 두 언어 모두 조건 분기를 값으로 만들 수 있다. Swift의 `if`·`switch` 표현식과 Kotlin의 `if`·`when` 표현식은 문법이 다르지만, 값을 만들려면 모든 실행 경로에서 결과가 정해져야 한다는 원칙은 같다.
- 열거형 상태는 Swift `switch`와 Kotlin `when`에서 모든 경우를 명시하면 새 상태가 추가될 때 누락을 발견하기 쉽다. 무조건 `default`나 `else`를 넣으면 이런 도움을 일부 잃을 수 있다.
- 두 언어 모두 컬렉션의 `indices`를 제공한다. 직접 범위를 만들 때 Swift `0..<n`, Kotlin `0 until n` 또는 `0..<n`은 끝값 `n`을 제외한다.

## 2. 개념 선택

> 단일 선택: 조건 분기와 반복에 대한 설명 중 가장 정확한 것을 하나 고른다.

- [ ] A. Swift의 `switch`는 값을 만들 수 없어서 반드시 먼저 빈 변수를 선언해야 한다.
- [ ] B. Kotlin의 `when` 표현식은 `enum class`의 모든 항목을 다뤄도 항상 `else`가 필요하다.
- [x] C. Swift와 Kotlin 모두 열거형 상태를 빠짐없이 분기하면 누락된 상태를 컴파일 단계에서 발견하는 데 도움이 된다.
- [ ] D. 컬렉션 요소의 값만 필요해도 항상 정수 인덱스 범위를 직접 만들어야 한다.

<details>
<summary>정답과 해설 확인</summary>

- 정답: C
- 해설: Swift `switch`와 Kotlin `when`은 열거형의 모든 경우를 명시할 수 있다. 새 상태가 추가되면 기존 분기가 더 이상 exhaustive하지 않음을 컴파일러가 알려 줄 수 있다. 값만 순회할 때는 Swift `for item in items`, Kotlin `for (item in items)`가 더 단순하다.

</details>

## 3. Swift 코드 읽기

> 단일 선택: 다음 코드의 출력으로 맞는 것을 고른다.

```swift
enum UploadState {
    case waiting, uploading, failed
}

let state = UploadState.uploading
let label = switch state {
case .waiting:
    "대기"
case .uploading:
    "업로드 중"
case .failed:
    "실패"
}

print(label)
```

- [ ] A. `대기`
- [x] B. `업로드 중`
- [ ] C. `실패`
- [ ] D. `switch`는 대입에 사용할 수 없어 컴파일 오류

<details>
<summary>정답과 해설 확인</summary>

- 정답: B
- 해설: `state`가 `.uploading`이므로 해당 branch의 문자열이 `label` 값이 된다. 세 `enum` case를 모두 다룬 exhaustive `switch` 표현식이므로 `default`는 필요하지 않다.

</details>

## 4. Kotlin 코드 읽기

> 단일 선택: 다음 코드의 출력으로 맞는 것을 고른다.

```kotlin
val steps = listOf(1200, 1800, 2200)
var total = 0

for (index in steps.indices) {
    total += steps[index]
}

println(total)
```

- [ ] A. `0`
- [ ] B. `2200`
- [x] C. `5200`
- [ ] D. `IndexOutOfBoundsException`

<details>
<summary>정답과 해설 확인</summary>

- 정답: C
- 해설: `steps.indices`는 리스트의 유효한 인덱스 `0`, `1`, `2`를 만든다. 각 값을 더하면 `1200 + 1800 + 2200 = 5200`이며 범위를 넘는 접근은 없다.

</details>

## 5. 올바른 코드 또는 오류 코드 선택

> 단일 선택: Swift 배열 `items`의 각 값과 인덱스를 함께 출력하는 코드로 가장 명확한 것을 고른다.

### A

```swift
for item in items {
    print(item)
}
```

- [ ] A 선택

### B

```swift
for index in items.indices {
    print(index, items[index])
}
```

- [x] B 선택

### C

```swift
for index in 0...items.count {
    print(index, items[index])
}
```

- [ ] C 선택

### D

```swift
for index in items.indices {
    print(items[index])
}
```

- [ ] D 선택

<details>
<summary>정답과 해설 확인</summary>

- 정답: B
- 해설: B는 `items.indices`로 유효한 인덱스를 순회하면서 인덱스와 값을 모두 출력한다. A와 D는 값만 출력해 요구사항의 인덱스를 빠뜨리고, C는 `items.count`를 포함해 마지막 접근에서 범위를 넘는다.

</details>

## 6. Swift · Kotlin 차이 선택

> 복수 선택 가능: 두 언어의 차이 또는 공통점을 올바르게 설명한 보기를 모두 고른다.

- [x] A. Swift의 `if`·`switch`와 Kotlin의 `if`·`when`은 조건에 따라 값을 만드는 형태로 사용할 수 있다.
- [x] B. Kotlin의 `if`를 값으로 사용할 때는 모든 조건 경로에서 값이 정해지도록 `else`가 필요하다.
- [x] C. Swift `items.indices`와 Kotlin `items.indices`는 각 컬렉션의 유효한 인덱스를 순회할 때 사용할 수 있다.
- [ ] D. Swift `0...items.count`와 Kotlin `0..items.size`는 끝값을 제외하므로 인덱스 접근에 안전하다.

<details>
<summary>정답과 해설 확인</summary>

- 정답: A, B, C
- 해설: 두 언어 모두 조건 분기를 값으로 만들 수 있다. Kotlin의 `if` 표현식에는 빠진 결과가 없도록 `else`가 필요하다. 두 언어의 `indices`는 유효한 인덱스를 표현한다. 반면 Swift `...`와 Kotlin `..`는 끝값을 포함하므로 `count`·`size`를 그대로 넣으면 마지막 접근에서 범위를 넘는다.

</details>
