> 인덱스 조회는 유효 범위를 전제로 하고, 키 조회는 값이 없을 가능성을 Optional·nullable로 표현한다. 변경 가능성은 Swift의 `let`·`var`와 Kotlin의 `List`·`MutableList`를 같은 의미로 단순 대응시키지 않는다.

## 1. 개념 읽기

### Swift에서 알아둘 점

Swift의 `Array`는 같은 타입의 값을 순서대로 저장한다. `[String]`은 `Array<String>`의 짧은 표기이며, 위치는 0부터 시작하는 인덱스로 접근한다. 반면 `Dictionary`는 키와 값의 쌍을 저장한다. 예를 들어 `[String: Int]`는 화면 이름을 키로, 알림 개수를 값으로 둘 수 있다. Dictionary는 삽입 순서가 앱의 의미가 되도록 설계된 자료구조로 보지 않는 편이 안전하다.

```swift
var cities = ["Seoul", "Prague", "Vienna"]
let firstCity = cities[0]                 // "Seoul"

let stationByCity = ["Prague": "Praha hl.n.", "Vienna": "Wien Hbf"]
let pragueStation = stationByCity["Prague"] // String?
```

배열의 유효한 범위를 벗어난 `cities[3]` 접근은 런타임 오류가 된다. 반대로 Dictionary의 키 조회는 키가 없을 수 있으므로 `Value?`를 반환한다. 따라서 API 응답이나 사용자 입력처럼 값 존재를 보장할 수 없는 곳에서는 `if let`, `??` 같은 Optional 처리가 필요하다.

`let`으로 선언한 Array·Dictionary는 그 변수로 컬렉션 자체를 바꿀 수 없고, `var`로 선언해야 `append`, 키 추가·삭제 같은 변경을 할 수 있다. 다만 컬렉션이 `class` 인스턴스를 담는 경우, `let`은 컬렉션 구조의 변경을 막는 것이지 그 안의 참조 객체가 다른 곳에서 변하는 것까지 막는다는 뜻은 아니다.

### Kotlin에서 알아둘 점

Kotlin의 `List`와 `Map`은 읽기 전용 인터페이스를 먼저 드러내는 표기다. `listOf`와 `mapOf`는 각각 `List`, `Map`을 만들며, `mutableListOf`, `mutableMapOf`는 요소를 추가·삭제할 수 있는 `MutableList`, `MutableMap`을 만든다. `val`은 변수 재대입을 막고, 컬렉션 인터페이스가 읽기 전용인지 변경 가능한지는 별도로 표현한다.

```kotlin
val cities: List<String> = listOf("Seoul", "Prague", "Vienna")
val firstCity = cities[0]                 // "Seoul"

val stationByCity: Map<String, String> =
    mapOf("Prague" to "Praha hl.n.", "Vienna" to "Wien Hbf")
val pragueStation = stationByCity["Prague"] // String?
```

Kotlin도 유효하지 않은 List 인덱스에 `[]`로 접근하면 예외가 날 수 있다. 안전하게 범위를 벗어난 결과를 nullable로 받고 싶다면 `getOrNull(index)`를 사용할 수 있다. `map[key]`의 결과도 키가 없을 수 있어 `Value?`다. `getValue(key)`는 키가 없을 때 예외를 내므로, 키의 존재가 계약으로 보장되는 경우에만 고르는 편이 알기 쉽다.

```kotlin
val maybeCity = cities.getOrNull(3)       // null
val editable = mutableListOf("Seoul")
editable.add("Prague")
```

### 두 언어의 핵심 차이

- Swift는 `let`·`var`로 컬렉션 변수의 변경 가능성을 주로 표현하고, Kotlin은 `List`/`Map`과 `MutableList`/`MutableMap`이라는 인터페이스 구분을 함께 사용한다.
- 두 언어 모두 Dictionary·Map에서 없는 키 조회를 값 없음으로 표현한다. Swift는 `Value?`, Kotlin은 `Value?`를 반환한다.
- 배열·리스트의 인덱스 접근은 순서와 범위를 전제로 한다. 값이 없을 가능성이 자연스러운 경계라면 인덱스 연산자를 무조건 쓰기보다 Swift의 `indices` 검사나 Kotlin의 `getOrNull`처럼 정책을 드러내는 방법을 고려한다.

## 2. 개념 선택

> 단일 선택: 컬렉션의 역할에 대한 설명 중 옳은 것을 하나 고른다.

- [ ] A. Swift Dictionary와 Kotlin Map은 키가 없어도 항상 기본 문자열을 반환한다.
- [ ] B. Array·List는 키로 값을 찾고 Dictionary·Map은 숫자 인덱스로만 값을 찾는다.
- [ ] C. Array·List는 순서와 인덱스로, Dictionary·Map은 키와 값의 연결로 값을 다룬다.
- [ ] D. `let`이나 `val`로 선언하면 컬렉션 안의 값도 언제나 변경 가능한 컬렉션이 된다.

> [!answer]- 정답과 해설 확인
> - 정답: C
> - 해설: Array·List는 순서가 있는 값 묶음이고, Dictionary·Map은 키로 값을 찾는 연결이다. 키가 없는 조회는 Optional·nullable일 수 있으며, `let`·`val`의 의미와 컬렉션 자체의 변경 가능성은 구분해야 한다.

## 3. Swift 코드 읽기

> 단일 선택: 다음 코드의 `station` 값으로 맞는 것을 고른다.

```swift
let stations = ["Prague": "Praha hl.n."]
let station = stations["Vienna"] ?? "역 정보 없음"
```

- [ ] A. `Praha hl.n.`
- [ ] B. `Vienna`
- [ ] C. `역 정보 없음`
- [ ] D. 컴파일 오류

> [!answer]- 정답과 해설 확인
> - 정답: C
> - 해설: `stations["Vienna"]`는 없는 키이므로 `nil`이다. `??`가 이를 받아 기본 문자열을 반환한다.

## 4. Kotlin 코드 읽기

> 단일 선택: 다음 코드의 `city` 값으로 맞는 것을 고른다.

```kotlin
val cities = listOf("Prague", "Vienna")
val city = cities.getOrNull(2) ?: "없음"
```

- [ ] A. `Prague`
- [ ] B. `Vienna`
- [ ] C. `없음`
- [ ] D. `IndexOutOfBoundsException`

> [!answer]- 정답과 해설 확인
> - 정답: C
> - 해설: 유효한 인덱스는 0과 1뿐이다. `getOrNull(2)`는 예외 대신 `null`을 반환하고, Elvis 연산자 `?:`가 `없음`을 선택한다.

## 5. 올바른 코드 선택

> 단일 선택: `names`에 없는 키가 들어와도 앱을 중단하지 않고 기본 표시 이름을 반환하는 올바른 코드 하나를 고른다.

### A

```swift
func displayName(_ key: String, names: [String: String]) -> String {
    names[key]!
}
```

- [ ] A 선택

### B

```swift
func displayName(_ key: String, names: [String: String]) -> String {
    names[key] ?? "알 수 없음"
}
```

- [ ] B 선택

### C

```kotlin
fun displayName(key: String, names: Map<String, String>): String {
    return names[key]!!
}
```

- [ ] C 선택

### D

```kotlin
fun displayName(key: String, names: Map<String, String>): String {
    return if (names[key] == null) key else "알 수 없음"
}
```

- [ ] D 선택

> [!answer]- 정답과 해설 확인
> - 정답: B
> - 해설: B는 키가 없을 때 Optional에 기본값을 제공한다. A·C는 값이 없으면 런타임 오류가 날 수 있고, D는 값이 있을 때 기본값을 반환하는 조건이 뒤집혀 있다.

## 6. Swift · Kotlin 차이 선택

> 복수 선택 가능: Swift와 Kotlin 컬렉션의 차이를 올바르게 설명한 보기를 모두 고른다.

- [ ] A. Kotlin의 `List`와 `MutableList` 구분은 읽기 전용 인터페이스와 변경 가능한 인터페이스를 드러낸다.
- [ ] B. Swift `Dictionary`와 Kotlin `Map`의 없는 키 조회는 일반적으로 값 없음 가능성을 표현한다.
- [ ] C. Swift Array의 범위를 벗어난 인덱스 접근은 자동으로 `nil`을 반환한다.
- [ ] D. Kotlin에서 `val`이면 `MutableList`의 `add`를 호출할 수 없다.

> [!answer]- 정답과 해설 확인
> - 정답: A, B
> - 해설: Swift의 Array 인덱스 접근은 범위를 벗어나면 런타임 오류가 날 수 있다. Kotlin의 `val`은 변수 자체의 재대입을 막을 뿐, 변수의 타입이 `MutableList`라면 요소 변경까지 막지는 않는다.
