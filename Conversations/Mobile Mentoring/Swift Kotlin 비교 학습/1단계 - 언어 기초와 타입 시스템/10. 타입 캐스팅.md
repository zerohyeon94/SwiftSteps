## 오늘의 학습 목표

- `Any`·`AnyObject`처럼 구체 타입이 불확실한 값을 읽을 때, 안전한 타입 캐스팅의 성공·실패 경계를 이해한다.
- Swift의 `as?`·`as!`·`is`와 Kotlin의 `as?`·`as`·`is`를 같은 모양이 아니라 실패 방식으로 비교한다.
- 외부 입력이나 여러 타입을 담은 컬렉션에서 강제 캐스팅을 기본값으로 두지 않는 이유를 설명한다.

## 1. 개념 읽기

타입 캐스팅은 이미 만들어진 값의 **실제 타입이 무엇인지 검사하거나 더 구체적인 타입으로 다루는 일**이다. 예를 들어 화면에서 전달받은 값이 `Any`이거나, 상위 타입 배열에 여러 하위 타입이 섞여 있으면 컴파일러는 특정 프로퍼티가 있는지 알 수 없다. 먼저 실제 타입을 확인해야 한다.

![[Assets/2026-09-02 - Swift Kotlin 타입 캐스팅 - 안전한 분기 흐름.svg]]

그림은 타입이 불확실한 값이 안전한 캐스팅의 성공·실패 분기로 나뉘는 구조를 단순화했다. 실제 값의 종류나 앱의 오류 정책을 모두 나타낸 것은 아니다.

### Swift에서 알아둘 점

- `value is Int`는 값이 `Int`인지 `Bool`로 검사한다.
- `value as? Int`는 변환에 성공하면 `Int?`, 실패하면 `nil`을 돌려준다. `if let`, `guard let`로 값을 안전하게 꺼내 쓴다.
- `value as! Int`는 성공을 확신할 수 있을 때만 쓰는 강제 캐스팅이다. 실제 타입이 다르면 실행 중 오류가 난다.
- 상속 관계에서 `as`는 이미 안전하게 성립하는 업캐스팅에 쓰일 수 있지만, 다운캐스팅에는 실패 가능성을 먼저 고려한다.

```swift
let raw: Any = 12

if let number = raw as? Int {
    print(number + 1)
} else {
    print("not an Int")
}
```

`raw`의 실제 값은 `Int`이므로 `as? Int`가 성공하고 `13`을 출력한다. 같은 코드에서 `raw`가 문자열이면 실패 경로로 가며 프로그램을 중단시키지 않는다.

### Kotlin에서 알아둘 점

- `value is Int`는 타입 검사다. 검사 뒤에는 조건 블록 안에서 smart cast가 적용될 수 있다.
- `value as? Int`는 성공하면 `Int?`, 실패하면 `null`을 돌려준다.
- `value as Int`는 실패하면 `ClassCastException`을 던질 수 있다. nullable 값과 강제 캐스팅은 별개의 문제라는 점도 구분한다.
- `as?` 결과에는 `?:`(Elvis 연산자)로 기본값을 둘 수 있지만, 기본값이 오류를 숨기지 않는지 판단해야 한다.

```kotlin
val raw: Any = "12"
val number = raw as? Int ?: 0
println(number + 1)
```

문자열은 `Int`가 아니므로 안전한 캐스팅 결과는 `null`이다. Elvis 연산자가 `0`을 고르고, 출력은 `1`이 된다.

### 두 언어의 핵심 차이

두 언어 모두 `is`로 검사하고 `as?`로 실패를 nullable 값으로 다룰 수 있다. 차이는 **강제 캐스팅의 실패를 어떻게 읽는가**에 있다. Swift의 `as!`는 실패 시 런타임 오류가 나고, Kotlin의 `as`는 실패 시 예외를 던진다. 따라서 외부 입력·서버 응답·다형 컬렉션처럼 타입을 완전히 확신하기 어려운 경계에서는 둘 다 안전한 캐스팅과 명시적인 실패 처리가 기본이다.

## 2. 개념 선택

> 단일 선택: 다음 설명 중 **옳은 것 하나**를 고르세요.

- [ ] A. Swift의 `as? Int`는 캐스팅 실패 시 프로그램을 즉시 종료한다.
- [ ] B. Kotlin의 `is Int`는 타입 검사 뒤에도 값을 `Int`처럼 다룰 수 없게 한다.
- [ ] C. Swift의 `as?`와 Kotlin의 `as?`는 실패를 각각 `nil`과 `null`로 표현한다.
- [ ] D. 실제 타입을 모르는 값에는 항상 `as!` 또는 `as`가 가장 안전하다.

> [!answer]- 정답과 해설
> - 정답: C
> - 해설: 두 안전한 캐스팅은 실패를 nullable 값으로 돌려 분기하게 한다. 강제 캐스팅인 Swift `as!`와 Kotlin `as`는 실패 시 런타임 문제로 이어질 수 있다.

## 3. Swift 코드 읽기

> 단일 선택: 다음 Swift 코드의 **실행 결과로 옳은 것 하나**를 고르세요.

```swift
let item: Any = "7"
let result = (item as? Int) ?? 3
print(result * 2)
```

- [ ] A. `14`
- [ ] B. `6`
- [ ] C. `7`
- [ ] D. 컴파일 오류

> [!answer]- 정답과 해설
> - 정답: B
> - 해설: `item`은 `String`이므로 `as? Int`는 `nil`이다. nil 병합 연산자 `??`가 `3`을 선택하고, 결과는 `6`이다.

## 4. Kotlin 코드 읽기

> 단일 선택: 다음 Kotlin 코드의 **실행 결과로 옳은 것 하나**를 고르세요.

```kotlin
val item: Any = 4
val text = if (item is Int) "${item + 2}" else "unknown"
println(text)
```

- [ ] A. `4`
- [ ] B. `6`
- [ ] C. `unknown`
- [ ] D. `ClassCastException`

> [!answer]- 정답과 해설
> - 정답: B
> - 해설: `item is Int` 조건이 참이므로 해당 블록 안에서 Kotlin이 `item`을 `Int`로 smart cast하고 2를 더한다.

## 5. 오류가 있는 코드 선택

> 단일 선택: 값의 실제 타입이 불확실한 상황에서 **오류 위험이 가장 큰 코드 하나**를 고르세요.

### A

```swift
if let title = value as? String {
    print(title)
}
```

- [ ] A 선택

### B

```kotlin
val count = value as? Int ?: 0
```

- [ ] B 선택

### C

```swift
let title = value as! String
print(title)
```

- [ ] C 선택

### D

```kotlin
if (value is String) println(value.length)
```

- [ ] D 선택

> [!answer]- 정답과 해설
> - 정답: C
> - 해설: `value`가 실제로 `String`이 아니라면 Swift의 `as!`는 런타임 오류를 낸다. 나머지는 안전한 캐스팅 또는 타입 검사 뒤에 사용하는 형태다. B의 기본값이 업무상 적절한지는 별도로 검토해야 한다.

- [ ] A. Swift `as?`의 실패 결과는 `nil`이고 Kotlin `as?`의 실패 결과는 `null`이다.
- [ ] B. Kotlin의 `is` 검사 뒤에는 조건 블록에서 smart cast가 적용될 수 있다.
- [ ] C. Swift `as!`와 Kotlin `as`는 실패해도 항상 nullable 결과를 돌려준다.
- [ ] D. 두 언어 모두 실제 타입이 불확실한 경계에서 안전한 캐스팅과 실패 처리를 표현할 수 있다.

> [!answer]- 정답과 해설
