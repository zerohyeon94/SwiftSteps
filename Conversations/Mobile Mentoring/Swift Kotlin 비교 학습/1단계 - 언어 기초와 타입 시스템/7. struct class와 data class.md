## 오늘의 학습 목표

Swift의 `struct`와 Kotlin의 `class`·`data class`를 단순히 “데이터를 담는 선언”으로 묶지 않고, **값/참조 의미**, **자동 생성되는 기능**, **중첩된 가변 객체를 복사할 때의 경계**를 분리해 읽는다.

![[Assets/2026-08-27 - Swift Kotlin struct class data class - 값과 참조 비교.svg]]

> `struct`는 값 타입이고 Kotlin의 `class`와 `data class`는 객체 참조를 다룬다. `data class`의 `copy()`도 중첩 참조를 깊게 복사한다는 뜻은 아니다.

## 1. 개념 읽기

### Swift에서 알아둘 점

`struct`는 값 타입이다. 변수에 대입하거나 함수에 전달할 때 독립된 값으로 다루는 것이 기본 의미다. 그래서 구조체 자체의 저장 프로퍼티를 인스턴스 메서드에서 바꾸려면 그 메서드에 `mutating`을 붙여, 호출자가 상태 변경을 명시적으로 볼 수 있게 한다.

```swift
struct Counter {
    var value = 0

    mutating func increment() {
        value += 1
    }
}
```

값 타입이라고 해서 안에 든 모든 것이 언제나 깊은 복사되는 것은 아니다. 구조체가 `class` 인스턴스나 가변 컬렉션처럼 참조 의미를 가진 값을 저장하면, 그 내부 참조를 어떻게 공유하는지는 별도로 살펴야 한다. “바깥 선언이 `struct`다”와 “모든 내부 상태가 완전히 독립적이다”는 같은 문장이 아니다.

### Kotlin에서 알아둘 점

Kotlin의 일반 `class`와 `data class`는 객체를 만든다. 두 변수는 같은 객체를 참조할 수 있다. 일반 클래스의 `==`는 기본적으로 `equals`를 호출하지만, `equals`를 별도로 정의하지 않은 경우에는 결국 참조 동일성에 가까운 비교가 된다.

`data class`는 주 생성자에 선언한 프로퍼티를 바탕으로 `equals()`·`hashCode()`·`toString()`·`componentN()`·`copy()`를 컴파일러가 생성해 주는 클래스다. 이 기능은 데이터 전송·표시·비교 코드를 줄여 주지만, `data class`가 Swift `struct`처럼 값 타입으로 바뀐다는 뜻은 아니다.

```kotlin
data class User(val name: String, val tags: MutableList<String>)

val first = User("Mina", mutableListOf("iOS"))
val second = first.copy()
second.tags += "Android"
```

위 코드에서 `copy()`는 `User` 객체를 새로 만들지만 `tags`의 `MutableList`까지 새로 만들지는 않는다. 따라서 `first.tags`와 `second.tags`는 같은 리스트를 가리킨다. 이를 얕은 복사라고 부른다.

### 두 언어의 핵심 차이

| 질문 | Swift `struct` | Kotlin `class` | Kotlin `data class` |
| --- | --- | --- | --- |
| 기본 의미 | 값 타입 | 참조 타입 객체 | 참조 타입 객체 |
| 대입 뒤 바깥 프로퍼티 변경 | 보통 독립된 값으로 다룸 | 같은 객체를 가리킬 수 있음 | 같은 객체를 가리킬 수 있음 |
| 데이터용 자동 기능 | 조건을 만족하면 `Equatable` 등 합성 가능 | 직접 정의 | `equals`·`hashCode`·`copy` 등 생성 |
| 중첩 참조의 복사 | 내부 참조는 따로 판단 | 참조 공유 여부를 따로 판단 | `copy()`도 기본은 얕은 복사 |

따라서 “Swift에서는 `struct`, Kotlin에서는 무조건 `data class`”라는 기계적 대응보다, 값 의미가 필요한지·객체 정체성이 필요한지·자동 생성 기능이 필요한지를 각각 먼저 묻는 편이 안전하다.

## 2. 개념 선택

> 단일 선택: 다음 설명 중 **옳은 것 하나**를 고른다.

- [ ] A. Kotlin `data class`는 Swift `struct`와 마찬가지로 항상 값 타입이다.
- [x] B. Swift `struct`의 저장 프로퍼티를 인스턴스 메서드에서 바꾸려면 보통 `mutating`을 표시한다.
- [ ] C. Kotlin 일반 `class`는 `copy()`를 자동 생성한다.
- [ ] D. Swift `struct`에 참조 타입 프로퍼티가 들어가면 그 참조도 언제나 깊게 복사된다.

> [!answer]- 정답과 해설 확인
> - 정답: B
> - 해설: `struct`의 인스턴스 상태를 바꾸는 메서드는 `mutating`으로 표시한다. `data class`도 클래스이므로 값 타입이 아니며, 일반 `class`는 `copy()`를 자동 생성하지 않는다. 구조체의 내부 참조가 깊게 복사되는지도 별도 문제다.

## 3. Swift 코드 읽기

> 단일 선택: 다음 코드의 **실행 결과**로 맞는 것을 고른다.

```swift
struct Counter {
    var value = 0
    mutating func increment() { value += 1 }
}

var first = Counter()
var second = first
second.increment()
print(first.value, second.value)
```

- [ ] A. `0 0`
- [x] B. `0 1`
- [ ] C. `1 1`
- [ ] D. `mutating`이 있어도 컴파일 오류

> [!answer]- 정답과 해설 확인
> - 정답: B
> - 해설: `second = first` 뒤 `second`는 별도의 `Counter` 값으로 다뤄진다. `second`만 변경했으므로 `first.value`는 0이고 `second.value`는 1이다.

## 4. Kotlin 코드 읽기

> 단일 선택: 다음 코드 뒤 `first.tags`와 `second.tags`의 **내용**으로 맞는 것을 고른다.

```kotlin
data class User(val tags: MutableList<String>)

val first = User(mutableListOf("Swift"))
val second = first.copy()
second.tags.add("Kotlin")
```

- [ ] A. `first`는 `[Swift]`, `second`는 `[Swift, Kotlin]`
- [x] B. 둘 다 `[Swift, Kotlin]`
- [ ] C. 둘 다 빈 리스트
- [ ] D. `copy()`는 가변 리스트를 받을 수 없어 컴파일 오류

> [!answer]- 정답과 해설 확인
> - 정답: B
> - 해설: `copy()`는 새 `User` 객체를 만들지만, 전달하지 않은 `tags` 인자에는 기존 리스트 참조를 사용한다. 따라서 두 프로퍼티가 같은 가변 리스트를 공유한다.

## 5. 오류가 있는 코드 선택

> 단일 선택: 다음 중 Swift `struct`의 저장 프로퍼티를 바꾸려 할 때 **오류가 있는 코드 하나**를 고른다.

### A

```swift
struct Score {
    var value = 0
    mutating func add() { value += 1 }
}
```

- [ ] A 선택

### B

```swift
struct Score {
    var value = 0
    func add() { value += 1 }
}
```

- [x] B 선택

### C

```kotlin
data class Score(val value: Int)
val next = Score(1).copy(value = 2)
```

- [ ] C 선택

### D

```kotlin
class Score(var value: Int)
val shared = Score(1)
```

- [ ] D 선택

> [!answer]- 정답과 해설 확인
> - 정답: B
> - 해설: `func add()`가 `struct`의 저장 프로퍼티를 바꾸려면 `mutating`이 필요하다. A는 이를 표시했고, C는 `data class`의 `copy` 사용이며, D는 가변 프로퍼티를 가진 일반 클래스 선언이다.

## 6. Swift · Kotlin 차이 선택

> 복수 선택: 다음 중 두 언어의 차이를 **올바르게 설명한 것 모두**를 고른다.

- [ ] A. Kotlin `data class`는 생성된 `copy()` 때문에 모든 중첩 객체까지 깊게 복사한다.
- [x] B. Swift `struct`는 값 타입이지만 내부에 든 참조 타입의 공유 여부는 별도로 살펴야 한다.
- [x] C. Kotlin `data class`는 주 생성자 프로퍼티를 바탕으로 `equals()`와 `hashCode()` 같은 기능을 생성할 수 있다.
- [ ] D. Swift `struct`와 Kotlin `data class`는 모두 기본적으로 같은 객체 참조를 공유한다.

> [!answer]- 정답과 해설 확인
> - 정답: B, C
> - 해설: Kotlin `data class`의 `copy()`는 기본적으로 얕은 복사다. `struct`는 값 타입이며 `data class`는 객체 참조를 다루는 클래스다. 둘의 자동 생성 기능과 복사 경계를 따로 봐야 한다.
