## 1. 개념 읽기

### Swift: 인스턴스가 완성되기 전에 저장 프로퍼티를 채운다

Swift의 `struct`와 `class`에 있는 저장 프로퍼티는 인스턴스가 사용되기 전에 값이 정해져야 한다. 선언할 때 기본값을 주거나, initializer가 값을 받는 방식이다.

```swift
struct Profile {
    let id: Int
    var nickname = "guest"
}

let profile = Profile(id: 7)
```

`id`는 `let`이므로 만들어진 뒤 다른 값으로 재대입할 수 없고, `nickname`은 `var`이므로 `var` 인스턴스에서는 바꿀 수 있다. `let profile`처럼 상수 `struct` 인스턴스의 `var` 프로퍼티를 바꾸는 것은 값 전체의 변경이므로 허용되지 않는다.

### Kotlin: 주 생성자 선언이 프로퍼티 선언이 될 수 있다

Kotlin에서는 클래스 머리의 주 생성자 매개변수 앞에 `val` 또는 `var`를 붙여 프로퍼티를 함께 선언할 수 있다.

```kotlin
class Profile(
    val id: Int,
    var nickname: String = "guest"
)

val profile = Profile(id = 7)
```

`id`는 읽기 전용이고 `nickname`은 변경 가능한 프로퍼티다. 다만 `val profile`은 **참조의 재대입**만 막는다. `nickname`이 `var`라면 `profile.nickname = "zero"`처럼 객체 내부의 변경은 가능하다. 이것은 Swift `struct`를 `let`으로 잡았을 때와 중요한 차이다.

### 생성 경로를 한 번에 보기

![[Assets/2026-08-28 - Swift Kotlin 프로퍼티 초기화 - 생성 경로.svg]]

> 그림은 기본값과 생성자 입력이 인스턴스를 완성하는 두 경로를 비교한다. Swift `let` 인스턴스와 Kotlin `val` 참조의 변경 가능성은 같은 뜻이 아니라는 점을 함께 표시했다.

| 질문 | Swift `struct` | Kotlin `class` |
|---|---|---|
| 생성 전에 값이 필요한가? | 기본값 또는 initializer로 모든 저장 프로퍼티를 초기화한다. | 주/보조 생성자나 프로퍼티 초기화로 필요한 값을 정한다. |
| 생성 시 값을 줄 수 있는가? | 기본값이 없는 저장 프로퍼티는 initializer 매개변수로 받는다. | 주 생성자의 `val`·`var` 매개변수로 자주 받는다. |
| 생성 뒤 값을 바꿀 수 있는가? | 프로퍼티가 `var`이고 인스턴스도 변경 가능한 경우 가능하다. | 프로퍼티가 `var`이면, 참조가 `val`이어도 내부 변경은 가능하다. |

## 2. 개념 선택

> 단일 선택: 초기화에 관한 설명 중 **옳은 것 하나**를 고른다.

- [ ] A. Swift의 모든 저장 프로퍼티는 선언 시 기본값만으로 초기화해야 한다.
- [ ] B. Kotlin 주 생성자의 매개변수는 `val`·`var`를 붙여도 프로퍼티가 될 수 없다.
- [x] C. Swift에서는 기본값이 없는 저장 프로퍼티를 initializer에서 채워 인스턴스를 완성할 수 있다.
- [ ] D. Kotlin의 `val` 프로퍼티는 생성 과정에서도 값을 받을 수 없다.

> [!answer]- 정답과 해설
> - 정답: C
> - 해설: Swift는 선언 시 기본값 또는 initializer를 통해 저장 프로퍼티를 초기화한다. Kotlin 주 생성자에서 `val`·`var`를 붙인 매개변수는 프로퍼티가 될 수 있다.

## 3. Swift 코드 읽기

> 단일 선택: 다음 코드의 `print` 결과로 **옳은 것 하나**를 고른다.

```swift
struct Profile { let id: Int; var nickname = "guest" }
let profile = Profile(id: 7)
print(profile.id, profile.nickname)
```

- [x] A. `7 guest`
- [ ] B. `0 guest`
- [ ] C. `7 nil`
- [ ] D. `id`에 기본값이 없어서 컴파일 오류

> [!answer]- 정답과 해설
> - 정답: A
> - 해설: `id`는 memberwise initializer로 전달했고, `nickname`은 선언한 기본값을 사용한다. `let`은 생성 뒤 재대입을 막는 것이지 생성 시 초기화까지 막지 않는다.

## 4. Kotlin 코드 읽기

> 단일 선택: 다음 코드의 실행 결과로 **옳은 것 하나**를 고른다.

```kotlin
class Profile(val id: Int, var nickname: String = "guest")
val profile = Profile(id = 7)
profile.nickname = "zero"
println(profile.nickname)
```

- [ ] A. `guest`
- [x] B. `zero`
- [ ] C. `val profile`이라 내부 `var` 변경이 금지되어 컴파일 오류
- [ ] D. 기본값이 있는 생성자 매개변수는 named argument와 함께 쓸 수 없어 컴파일 오류

> [!answer]- 정답과 해설
> - 정답: B
> - 해설: `val profile`은 `profile` 참조 자체를 다른 객체로 바꾸지 못하게 한다. `nickname`은 `var` 프로퍼티이므로 해당 객체 내부에서 변경할 수 있다.

## 5. 오류가 있는 코드 선택

> 단일 선택: 인스턴스가 만들어질 때까지 필요한 값을 정할 수 없어 **컴파일 오류가 나는 코드 하나**를 고른다.

### A

```swift
struct Badge { let level: Int; init(level: Int) { self.level = level } }
```

- [ ] A 선택

### B

```swift
struct Badge { var title = "new" }
```

- [ ] B 선택

### C

```kotlin
class Badge { val level: Int }
```

- [x] C 선택

### D

```kotlin
class Badge(val level: Int = 1)
```

- [ ] D 선택

> [!answer]- 정답과 해설
> - 정답: C
> - 해설: Kotlin의 `level`은 `val` 프로퍼티인데 선언·initializer·생성자 어디에서도 초기화하지 않았다. A·B·D는 모두 인스턴스가 준비되기 전에 값을 정한다.

## 6. Swift · Kotlin 차이 선택

> 복수 선택: 두 언어의 차이를 **올바르게 설명한 것을 모두** 고른다.

- [x] A. Swift의 `let`으로 선언한 `struct` 인스턴스는 `var` 저장 프로퍼티라도 바꿀 수 없다.
- [ ] B. Kotlin에서 `val`로 잡은 객체는 그 객체의 모든 `var` 프로퍼티를 항상 바꿀 수 없다.
- [x] C. Kotlin의 주 생성자 매개변수에 `val`·`var`를 붙이면 생성자 입력과 프로퍼티 선언을 함께 표현할 수 있다.
- [ ] D. Swift `struct`의 memberwise initializer와 Kotlin 주 생성자는 문법·생성 규칙이 완전히 같으므로 구분할 필요가 없다.

> [!answer]- 정답과 해설
> - 정답: A, C
> - 해설: Swift 값 타입 인스턴스를 `let`으로 잡으면 내부 `var` 변경도 값 전체의 변경이다. Kotlin `val`은 참조 재대입을 막을 뿐 `var` 프로퍼티의 내부 변경까지 일반적으로 막지 않는다. 두 언어의 생성 문법과 자동 생성 조건도 다르다.
