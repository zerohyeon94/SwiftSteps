## 오늘의 학습 목표

- Swift의 `T?`가 `Optional<T>`의 축약 표기이며 `nil`을 담을 수 있음을 이해한다.
- Kotlin의 `T?`와 안전 호출 `?.`, Elvis 연산자 `?:`로 `null`을 처리하는 흐름을 읽는다.
- 외부 데이터가 비어 있을 가능성을 타입과 분기에서 드러내고, `!`·`!!`를 기본 해법으로 쓰지 않는 이유를 설명한다.

## 1. 개념 읽기

### Swift에서 알아둘 점

Swift의 일반 타입 `String`에는 `nil`을 넣을 수 없다. 값이 없을 가능성을 타입에 표현하려면 `String?`처럼 `?`를 붙인다. 이것은 `Optional<String>`의 짧은 표기다. Optional은 실제 값인 `.some(값)` 또는 값 없음인 `.none`(`nil`) 중 하나를 표현한다.

값을 쓰기 전에는 Optional을 풀어야 한다. `if let`, `guard let`은 값이 있는 경우에만 내부에서 non-optional 값으로 다룰 수 있게 한다. `?.`는 값이 있을 때만 다음 멤버를 호출하고, `??`는 값이 없을 때의 기본값을 제공한다.

```swift
func displayName(_ nickname: String?) -> String {
    guard let nickname, !nickname.isEmpty else {
        return "이름 미설정"
    }
    return nickname
}

let label = displayName(nil) // "이름 미설정"
```

`nickname!`처럼 강제 언래핑하면 값이 실제로 `nil`일 때 앱이 종료될 수 있다. 테스트용 고정값처럼 `nil`이 절대 불가능함을 코드 주변에서 증명할 수 있는 아주 좁은 경우가 아니라면, 분기·기본값·오류 처리로 가능성을 드러내는 편이 낫다.

### Kotlin에서 알아둘 점

Kotlin의 기본 타입 `String`도 `null`을 허용하지 않는다. `String?`로 선언해야 `null`을 담을 수 있다. nullable 값을 그대로 `uppercase()` 같은 non-null 멤버에 넘길 수 없으므로, 호출 전에 검사하거나 안전 호출을 사용한다.

`name?.uppercase()`는 `name`이 null이 아니면 대문자로 바꾸고, null이면 결과도 null이다. 이어서 `?:`(Elvis 연산자)를 쓰면 null일 때의 대체값을 제공할 수 있다.

```kotlin
fun displayName(nickname: String?): String {
    return nickname?.takeIf { it.isNotEmpty() } ?: "이름 미설정"
}

val label = displayName(null) // "이름 미설정"
```

`!!`는 값이 null이 아니라고 강제한다. 실제로 null이면 `NullPointerException`이 발생한다. Java 플랫폼 타입처럼 null 가능성이 명확하지 않은 경계에서는 특히 반환 타입과 검증 지점을 먼저 확인하는 편이 안전하다.

### 두 언어의 핵심 차이

- Swift의 Optional은 `Optional<T>`라는 열거형으로 값 있음과 없음의 두 상태를 표현한다. Kotlin의 nullable type은 타입 표기에 null 허용 여부를 포함한다.
- 두 언어 모두 `?`로 null 가능성을 드러내지만, Swift는 `if let`·`guard let`의 optional binding을 자주 쓰고 Kotlin은 `?.`·`?:`와 스마트 캐스트를 자주 조합한다.
- `!`와 `!!`는 타입 검사를 우회해 런타임 실패 가능성을 호출 지점으로 옮긴다. 외부 API·사용자 입력·저장소 데이터처럼 비어 있을 수 있는 경계에서는 기본값, 오류 상태, 재시도 또는 명시적 분기로 처리할 정책을 정해야 한다.

## 2. 개념 선택

> 단일 선택: nullable 타입에 대한 설명 중 가장 정확한 것을 하나 고른다.

- [x] A. Swift `String?`와 Kotlin `String?`은 값이 없을 가능성을 타입에 표시한다.
- [ ] B. Swift Optional은 값을 풀지 않아도 언제나 `String`처럼 멤버를 호출할 수 있다.
- [ ] C. Kotlin nullable type에는 `null`을 저장할 수 없고 빈 문자열만 저장할 수 있다.
- [ ] D. `!`와 `!!`는 null일 때도 기본값을 안전하게 제공한다.

> [!answer]- 정답과 해설 확인
> - 정답: A
> - 해설: 두 언어의 `?` 표기는 값이 없을 가능성을 타입에서 표현한다. Swift는 optional binding 또는 `?.`·`??`로, Kotlin은 null 검사·안전 호출·Elvis 연산자로 값을 다룬다. `!`와 `!!`는 null일 때 런타임 실패를 일으킬 수 있다.


## 3. Swift 코드 읽기

> 단일 선택: 다음 코드의 출력으로 맞는 것을 고른다.

```swift
let nickname: String? = nil
print(nickname ?? "익명")
```

- [ ] A. `nil`
- [x] B. `익명`
- [ ] C. 컴파일 오류
- [ ] D. 런타임 오류

> [!answer]- 정답과 해설 확인
> - 정답: B
> - 해설: `??`는 왼쪽 Optional에 값이 있으면 그 값을, 없으면 오른쪽 기본값을 사용한다. 따라서 `nickname`이 nil인 이 코드에서는 `익명`을 출력한다.


## 4. Kotlin 코드 읽기

> 단일 선택: 다음 코드의 출력으로 맞는 것을 고른다.

```kotlin
val nickname: String? = null
println(nickname?.uppercase() ?: "익명")
```

- [ ] A. `NULL`
- [ ] B. 빈 문자열
- [x] C. `익명`
- [ ] D. `uppercase()` 호출에서 컴파일 오류

> [!answer]- 정답과 해설 확인
> - 정답: C
> - 해설: 안전 호출 `?.`는 nickname이 null이면 null을 돌려준다. 그 결과에 Elvis 연산자 `?:`가 적용되어 `익명`이 출력된다.


## 5. 올바른 코드 선택

> 단일 선택: `name`이 없을 때도 앱을 종료하지 않고 대문자 표시 이름을 반환하는 코드 하나를 고른다.

### A

```swift
func display(_ name: String?) -> String {
    name.uppercased()
}
```

- [ ] A 선택

### B

```swift
func display(_ name: String?) -> String {
    name?.uppercased() ?? "GUEST"
}
```

- [x] B 선택

### C

```kotlin
fun display(name: String?): String {
    return name!!.uppercase()
}
```

- [ ] C 선택

### D

```kotlin
fun display(name: String?): String {
    return name ?: "GUEST".uppercase()
}
```

- [ ] D 선택

> [!answer]- 정답과 해설 확인
> - 정답: B
> - 해설: B는 안전 호출로 값이 있을 때만 대문자로 바꾸고, 없을 때는 `GUEST`를 반환한다. A는 Optional을 바로 사용해 컴파일되지 않는다. C는 null에서 예외가 난다. D는 null일 때만 기본값을 대문자로 만들므로, 이름이 있을 때도 항상 대문자로 표시한다는 요구를 만족하지 않는다.


## 6. Swift · Kotlin 차이 선택

> 복수 선택 가능: 두 언어의 null 안전성을 올바르게 설명한 보기를 모두 고른다.

- [x] A. Swift의 `if let`·`guard let`과 Kotlin의 null 검사·안전 호출은 nullable 값을 안전한 범위에서 non-null 값으로 다루는 데 쓰인다.
- [ ] B. Kotlin의 `String?`은 Java 연동을 포함해 어떤 상황에서도 `NullPointerException`을 만들 수 없다.
- [x] C. Swift는 `nil`, Kotlin은 `null`이라는 값 없음 표현을 사용한다.
- [x] D. Swift의 Optional과 Kotlin의 nullable type은 모두 외부 데이터가 비어 있을 수 있다는 계약을 타입에서 드러내는 데 쓸 수 있다.

> [!answer]- 정답과 해설 확인
> - 정답: A, C, D
> - 해설: 두 언어 모두 nullable 값을 안전하게 처리할 문법을 제공하지만, Kotlin도 `!!`이나 Java 상호운용의 플랫폼 타입 등으로 런타임 null 문제가 생길 수 있다. null 안전성은 문법만이 아니라 데이터 경계의 검증 정책까지 포함한다.
