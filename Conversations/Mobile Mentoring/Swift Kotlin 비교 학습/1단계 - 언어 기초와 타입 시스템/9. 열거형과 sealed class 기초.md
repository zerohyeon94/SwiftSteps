## 오늘의 목표

Swift의 `enum`과 Kotlin의 `sealed class`를, 가능한 상태를 제한하고 상태별 처리를 빠뜨리지 않게 돕는 도구로 이해한다. 값 자체를 열거할 때와 서로 다른 데이터를 가진 상태들을 묶을 때를 구분해 본다.

## 핵심 개념

로딩 결과는 “시작 전”, “개수와 함께 성공”, “메시지와 함께 실패”처럼 서로 다른 상태를 가진다. 문자열로 상태를 적으면 오타나 조합 오류가 생기기 쉽다. `enum`과 `sealed class`는 가능한 상태의 집합을 코드로 드러내고, `switch`·`when`에서 상태별 처리를 모아 보게 한다.

- Swift `enum`은 case를 나열하고 각 case에 연관 값(associated value)을 붙일 수 있다.
- Kotlin `sealed class`는 제한된 하위 타입 계층을 만든다. 값이 하나뿐인 상태는 `data object`, 데이터를 가진 상태는 `data class`로 표현할 수 있다.
- 두 언어 모두 상태를 분기할 때 모든 경우를 의식하게 하지만, 컴파일러가 완전한 분기를 요구하는 조건은 `switch`·`when`의 사용 방식과 언어 규칙에 따라 다르다.

![[Assets/2026-08-29 - Swift Kotlin enum sealed class - 상태 분기 구조.svg]]

그림은 하나의 로딩 상태가 세 가지 가능한 분기로 제한되는 구조를 비교한다. 실제 앱의 상태 수나 화면 흐름을 나타낸 것이 아니라, 상태와 함께 전달되는 데이터의 관계만 단순화했다.

## 코드·문법 예시 읽기

### Swift: case와 연관 값

~~~swift
enum LoadState {
    case idle
    case loaded(count: Int)
    case failed(message: String)
}

let state = LoadState.loaded(count: 3)
switch state {
case .loaded(let count):
    print(count)
case .idle, .failed:
    print("not loaded")
}
~~~

`loaded` case가 `Int`를 함께 들고 있으므로 분기 안에서 값을 꺼낼 수 있다. 위 코드의 출력은 `3`이다.

### Kotlin: 제한된 하위 타입과 when

~~~kotlin
sealed class LoadState {
    data object Idle : LoadState()
    data class Loaded(val count: Int) : LoadState()
    data class Failed(val message: String) : LoadState()
}

val state: LoadState = LoadState.Loaded(3)
val text = when (state) {
    is LoadState.Loaded -> "${state.count}"
    is LoadState.Failed -> "error"
    LoadState.Idle -> "idle"
}
print(text)
~~~

`LoadState`를 상속하는 상태가 제한되어 있으므로, `when`은 각 하위 타입을 기준으로 읽을 수 있다. 위 코드의 출력은 `3`이다.

## 선택 문제

### 1. 단일 선택 — 올바른 설명을 하나 고르세요.

- [ ] A. Swift enum의 모든 case에는 같은 타입의 연관 값이 반드시 필요하다.
- [ ] B. Kotlin sealed class는 제한된 하위 타입으로 상태를 표현할 수 있다.
- [ ] C. Kotlin의 when은 sealed class를 다룰 수 없다.
- [ ] D. Swift enum은 상태 값을 표현하는 데 쓸 수 없다.

> [!answer]- 정답과 해설
> 정답은 **B**다. sealed class는 관련된 하위 타입을 제한된 계층으로 묶는 데 쓸 수 있다. Swift enum의 연관 값은 선택 사항이며, 두 언어 모두 상태를 표현할 수 있다.

### 2. 단일 선택 — 아래 Swift 코드의 실행 결과를 고르세요.

~~~swift
enum ResultState { case success(value: Int); case failure }
let result = ResultState.success(value: 8)
switch result {
case .success(let value): print(value / 2)
case .failure: print(0)
}
~~~

- [ ] A. `4`
- [ ] B. `8`
- [ ] C. `0`
- [ ] D. 컴파일 오류

> [!answer]- 정답과 해설
> 정답은 **A**다. `success(value: 8)`에서 연관 값을 꺼내 2로 나누므로 `4`를 출력한다.

### 3. 단일 선택 — 아래 Kotlin 코드의 실행 결과를 고르세요.

~~~kotlin
sealed class Connection {
    data object Offline : Connection()
    data class Online(val users: Int) : Connection()
}
val connection: Connection = Connection.Online(2)
val message = when (connection) {
    Connection.Offline -> "off"
    is Connection.Online -> "on: ${connection.users}"
}
println(message)
~~~

- [ ] A. `off`
- [ ] B. `on: 2`
- [ ] C. `2`
- [ ] D. 컴파일 오류

> [!answer]- 정답과 해설
> 정답은 **B**다. 실제 값은 `Online(2)`이고 해당 분기에서 `users`를 문자열에 넣는다.

### 4. 단일 선택 — Swift와 Kotlin의 차이에 대한 올바른 설명을 하나 고르세요.

- [ ] A. Swift enum은 연관 값을 가질 수 없고 Kotlin sealed class만 데이터를 가질 수 있다.
- [ ] B. Kotlin sealed class의 각 상태는 object나 data class처럼 서로 다른 하위 타입으로 나타낼 수 있다.
- [ ] C. Swift의 switch는 enum case를 분기할 수 없다.
- [ ] D. Kotlin sealed class는 상속 관계와 무관한 문자열 목록이다.

> [!answer]- 정답과 해설
> 정답은 **B**다. Kotlin sealed class는 여러 하위 타입을 제한하는 구조이며, 단일 상태와 데이터를 가진 상태를 서로 다르게 선언할 수 있다. Swift enum도 case와 연관 값으로 비슷한 상태 모델링을 할 수 있지만 문법과 타입 계층은 다르다.
